# ROADMAP — 作る順序

文書の層と、矛盾したときにどの文書が勝つかは `CLAUDE.md`「文書の層」が持つ。
決定と経緯は `docs/adr/`。

## この文書の分担

| 持つもの | 置き場 |
|---|---|
| 順序・順序の理由・完了条件の閾値 | この文書 |
| 実行単位と状態 | GitHub Issues |
| 決定と経緯 | `docs/adr/` |
| 現況 | `ARCHITECTURE.md` |
| 検証と実行環境 | `HARNESS.md` |

ここに他の層の内容を複製しない（複製した瞬間から腐る）。

## この文書は状態を持たない

ステップに ✓ や進捗を書かない。完了は issue の close で確定する。
束の issue がすべて閉じたステップは依存グラフと順序の表から消し、閉じた記録は git が持つ。
この文書を改訂するのは、**順序か規約が変わったときだけ**。
どこまで issue へ降りているかは GitHub Issues の並びが持つ。

## 進め方の横断規約

- **コミットの前に必ず**: `web/` で `pnpm check`（本文は `HARNESS.md`「判定の口」）
- **1 issue = 1 セッション = 1 PR**。中途半端な feature を残してセッションを跨がない
- PR 本文に `closes #N` を書く
- 署名は `CLAUDE.md` の git 節（author は人間名義、`Co-authored-by: Claude`、prefix は変更の型）
- **1セッションに収まらない実装は、着手の前に issue へ割る**。割る単位は「一つの issue で `pnpm check` が緑になる」
- GitHub へ到達できないセッションの扱いは `HARNESS.md`「実行環境」が持つ

## 完了条件は二本に分ける

issue の完了条件は**機械判定**と**人間の判定**に分ける。

- **機械判定** — `pnpm check` が緑、特定のテストが通る、ファイルが存在する等。
  **これを満たせば close してよい**
- **人間の判定** — 実機の手触りと見た目の確認（`HARNESS.md`「1. 検証の層構造」）。**close を妨げない**。
  滞留するなら独立 issue を立てる

分ける理由は、後者が待ち行列になると前者まで止まるから。

## 依存グラフ

```
S5 ──> S8 ──> S9 (任意)
S7
```

S7 は S5 と S8 のどちらとも並行できる。
S8 は一塊ではない。フッタと README の画像は S5 の後で、README の本文は S5 を待たずに着手でき、束の中で着手条件が割れる（理由は下の表の S8 行）。
人間の作業（S7 のデータ補正）は Claude の作業と非同期に進む。

## 順序の理由

ステップは issue の束の見出しであって、作業単位ではない（作業単位は issue）。
個々の issue には載らない情報なので、ここが持つのは**なぜこの順か**と**そのステップが閉じたと言える閾値**の二つだけである。

| ステップ | 内容 | なぜこの順か | 閉じた判定 |
|---|---|---|---|
| **S5** | 一覧パネル + 選択同期 + 近接の三つ（`ARCHITECTURE.md`「シリーズの近接」） | 近接の三つは選択を起点にするので、selection の消費者が地図とパネルの二者に揃うここへ同居させる | パネル⇄地図の双方向選択が一致し、関連シリーズ行・同時代ハイライト・tag 絞り込みが動く。位置なしのシリーズがパネルの別区画に出る |
| **S7** | 手元の管理画面 + 全シリーズデータ叩き台 | 代表点を JSON へ手で書くのは無理なので、人間が値を直すための管理画面をデータ叩き台と同じ束に置く | 公式一覧の全シリーズが `series.json` に載り、代表点か位置なしを宣言してバリデーションを通る（「完了条件の閾値」の1） |
| **S8** | 仕上げ + 出典表記 + デプロイ + README | フッタは地図の上に載る S5 のパネルと置き場を争うので S5 の後。README の本文は、書く設計判断が既に `docs/adr/` に揃っているので S5 と S7 を待たない。README の画像は一覧パネルの入った画面を写すので S5 の後 | 公開 URL で全機能が動作し、出典表記がフッタ・README・`/about` に揃い、README が提示可能（「完了条件の閾値」の3） |
| **S9** | （任意）第二段階: 事物に年範囲と精緻な図形を持たせる | 版図や経路の正確さは調査がボトルネックで、閾値の内に置くと閉じないので、着手は S8 の後にする。OpenHistoricalMap 連動はこの中の取得元候補の一つ（#96） | 閾値の外なので閉じる判定を持たない。着手した issue が個別に閉じる |

## 完了条件の閾値（ポートフォリオとして見せられる品質に届いたと言える基準）

次の3点が揃ったら、ポートフォリオとして見せられる品質に届いたとみなす。
3点を満たしてもこのプロジェクトは自動では閉じず、閉じるかは人間が決める。

3点は次のとおり:

1. **公開 URL で地図アプリが動作し、公式一覧の全シリーズが地図に載る**

   「公式一覧」の定義:

   - 出典は公式 RSS `https://anchor.fm/s/8c2088c/podcast/rss` の `itunes:season`。
     番組サイト cotenradio.fm はドメインが失効して第三者の広告サイトに変わっており、
     coten.co.jp の COTEN RADIO ページも配信基盤へのリンクだけでシリーズを列挙していないので、
     一覧の正はフィードしか残っていない
   - 1 シリーズ = `itunes:season` の 1 値と数える
   - `itunes:season` を持たない回（番外編・特別編・告知）は数えない
   - `itunes:season` に番外編の通し番号が入った 3 件（115・116・117）も数えない。
     タイトルが `【番外編＃` で始まることで判別できる
   - 「COTEN RADIOショート」も独立した season 番号を持つので 1 シリーズとして数える
   - シリーズは今後も増えるので、閾値を判定する時点のフィードを正とする

   判定は「シリーズ数」——上の定義で数えた全シリーズが `series.json` に存在し、
   代表点か位置なしを宣言してバリデーションを通ること。
   代表点の位置と年代の精度は叩き台品質で可。
   版図や経路の精緻な図形は閾値の外（S9）
2. **`pnpm sync` による RSS 由来の新エピソード追加パイプラインが回る**
   （新規取得 → season 割当 → 未割当の数え上げまで）
3. **README がポートフォリオとして提示可能**（設計判断・スクショ・技術スタック）

## 精緻化の規律

全ステップを一度に issue へ降ろさない。
直近 2〜3 ステップのみ関数シグネチャとテストケースまで降ろし、遠いものは粗いまま置く。
手前の issue が尽きたら次の束を割る。
遠い先まで降ろすと、手前で分かったことが後ろの全部を書き直させる。
