# 0045. 判定の口は `web/` で打つ `pnpm check` の一本で、踏襲しているツールチェーンの規約と同じ形にする（0009 を supersede）

- **状態**: 採用
- **決定日**: 2026-09-14（口を `pnpm check` にした決定そのものは 0009 の 2026-08-25 のまま）
- **関係する ADR**: 0009（これを supersede する。決定は変えず帰結を現況に合わせる）、0002（0009 が supersede した）、0001（`next build` を含める理由）、0014（スモークを口の末尾に足す）、0016（スモークを Playwright で回す）

## 文脈

0009 の帰結は、踏襲しているツールチェーンの規約（このリポジトリの外で決めている）の「タスクランナー = mise tasks」からの逸脱を `HARNESS.md`「判定の口」に明記すると求めていた。
その規約は 2026-08-26 に「タスクランナー = その言語のマニフェスト」へ改まり、逸脱は解消した。
0009 は本文を変えずに末尾へ後日の事実を追記し、`HARNESS.md` は逸脱でない旨へ書き換えた後、PR #226 でその記述ごと消した。
0009 を単体で開いた読み手は、いまも帰結の「逸脱を明記する」を現行と読む。
ADR 規約 4 は「決定は生きていて帰結だけが古くなった場合も、帰結を直した新しい版を書く」なので、帰結を現況に合わせたこの版を書く。

## 決定

`web/` で打つ `pnpm check` の一本を機械判定の口にする。

| 段 | script | 実体 |
|---|---|---|
| L0 型 | `typecheck` | `tsc --noEmit` |
| L1 静的 | `lint` | `biome ci .` と `node scripts/lint-comments.ts` |
| L2 ユニット | `test` | `vitest run`（`catalog/` の検査を含む） |
| L3 ビルド | `build` | `next build` |
| L4 スモーク | `smoke` | `playwright test --project=smoke` |

並びは安いものから落とす。
タスクは `web/package.json` の scripts が持ち、`mise.toml` は `[tools]` だけを持って `run = "pnpm check"` の薄いラッパを置かない。

## 理由

0009 の理由をそのまま引き継ぐ。

- issue の完了条件を一つのコマンドへ集約する。判定の口が複数あると、どれが緑なら閉じてよいかが毎回議論になる
- タスクを `package.json` の scripts に置くのは、踏襲しているツールチェーンの規約が JS/TS 系の設定の置き場を `package.json` と定めており、タスクだけを別ファイルへ出すと置き場が二つに割れるため
- `mise.toml` に薄いラッパを置かないのは、口が一本に見えて二本ある状態が、そもそも避けようとしたものだから
- `next build` を含めるのは、static export がビルド時にしか壊れない失敗を持つため（0001）

採らなかった案。

- 0009 の帰結を本文の中で直す ／ 規約 4 が本文の書き換えを禁じる
- 0009 の末尾の追記だけで済ませる ／ 帰結の節を読んだ読み手が追記まで辿らないと現行が分からない

## 帰結

- 0009 は supersede 済みになる（本文は残す）
- 踏襲しているツールチェーンの規約と同じ形なので、逸脱の記録を持つ文書は無い
- ランタイムの版は `mise.toml` の `[tools]` が固定し、CI（`.github/workflows/check.yml`）は同じ `pnpm check` を `web/` で回す
- 口へ段を足すときは `check` script の連鎖へ足し、別の script を「これが緑なら閉じてよい」と言える口にしない（0014 のスモークはこの形で足した）

## 覆る条件

踏襲しているツールチェーンの規約が「タスクランナー = その言語のマニフェスト」を改め、タスクの置き場を `package.json` の外へ定めたとき。
