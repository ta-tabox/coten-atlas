# 画面の操作と配置の検査をスモークから分け、E2E の段として `pnpm check` のスモークの後に置く（20261112-smoke-mobile-webkit-chromium を supersede）

- **状態**: 採用
- **決定日**: 2026-11-24
- **関係する ADR**: 20261112-smoke-mobile-webkit-chromium（これを supersede する）、20260914-pnpm-check-current-form（段は `check` script の連鎖へ足す）、20260829-playwright-runner（ブラウザを立てる検証を Playwright で回す）

## 文脈

20261112-smoke-mobile-webkit-chromium は、スモークを三つの端末の条件で回し、スマホの二つの条件では画面の配置の崩れもスモークで見ると決めた。
その後、スモークの spec の置き場へ、一覧パネルや地図の円を押すと詳細カードが開くかを見る操作の検査と、ヘッダー・出典表記・シート・一覧パネルの矩形を比べる配置の検査が、デスクトップの条件の分も含めて入った。
自足の検査は配信の機構が変わらない限り書き換わらないが、操作と配置の検査は画面の部品を直すたびに書き換わる。
地図の上に独自に描く要素の検査はこれからも増えるので、同じ置き場と同じ project に混ぜたままにすると、自足の検査が何を守っているのかが spec の一覧から読めなくなる。

## 決定

ブラウザを立てる検証を、見るものごとに二つの段に分ける。

| 段          | 見るもの                                                                                                                        | script       |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| L4 スモーク | 静的成果物が自足していること（同一オリジンへの 4xx / 5xx が無い・`console.error` が出ない・地図の canvas が viewport 大で立つ） | `pnpm smoke` |
| L5 E2E      | 画面の操作（押すと開くか・選択中の表示になるか）と配置（部品の矩形が重ならず、画面の外へ出ないか）                              | `pnpm e2e`   |

L5 は `pnpm check` の連鎖で L4 の後に置き、別の「これが緑なら閉じてよい」エントリポイントにしない。

二つの段は同じ端末の条件で回す。

| 条件         | ブラウザ | viewport の出どころ                               |
| ------------ | -------- | ------------------------------------------------- |
| デスクトップ | Chromium | 固定の寸法（決定時点は 1440×900）                 |
| iPhone       | WebKit   | Playwright の `devices`（決定時点は `iPhone 13`） |
| Android      | Chromium | Playwright の `devices`（決定時点は `Pixel 7`）   |

配信物を開く機構（`BASE_PATH` 込みの配信・外部への通信の遮断・スタイルを合成のフィクスチャで返すこと）は二つの段で共有し、L5 も外部へ出ない。

**地図が正しく描画されているかと、iOS の Safari のタッチの手触りは見ない。**
それは人間の目視と実機の確認に残す（20261112-smoke-mobile-webkit-chromium から変わらない）。

段ごとの spec の置き場・project の名前・端末の条件の寸法の現況は、`docs/HARNESS.md`「検証の層構造」と `web/playwright.config.ts` が持つ。

## 理由

- 自足の検査と操作・配置の検査は、書き換わる契機が違う（前者は配信の機構、後者は画面の部品）
- 置き場と script を分ければ、spec の一覧と script の名前から、各段が守るものを読める
- 端末の条件を共有するので、CSS の解釈の差による崩れを各エンジンで捕まえる性質は保たれる
- 段を `pnpm check` の中に置くので、判定のエントリポイントは一本のまま保たれる（20260914-pnpm-check-current-form）

以下は 20261112-smoke-mobile-webkit-chromium の理由から変わらない部分の複写である。

- iPhone の Safari と Android の Chrome は描画エンジンが違うので、CSS の解釈の差（`dvh`・`-webkit-` 接頭辞の擬似要素・`overscroll-behavior`）による崩れは、その端末と同じエンジンでなければ捕まらない
- 部品の重なりは 4xx も `console.error` も出さないので、自足の三点だけでは捕まらない
- Playwright の WebKit は iOS の WebKit の `<input type="range">` のタッチの処理を通らず、スワイプを送る API も持たないので、タッチの手触りは実機に残す
- ヘッドレスのブラウザは地図を描ける
- 外部を遮断しても配信物の自足の穴は捕まる
  maplibre はスタイルにソースが無くても worker を要求するため、404 の側が残る

| 採らなかった案                                       | 採らなかった理由                                                                     |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 操作と配置の検査をスモークに置いたままにする         | 自足の検査が何を守るかが spec の一覧から読めず、画面を直すたびにスモークが書き換わる |
| E2E を `pnpm check` の外の別のエントリポイントにする | 「これが緑なら閉じてよい」と言えるエントリポイントが二本になる                       |
| E2E をデスクトップの条件だけで回す                   | スマホの二つの条件で配置の崩れを見る検査が、どの段にも残らなくなる                   |
| 配信物を開く機構を E2E 用に別に持つ                  | 外部への通信の遮断とフィクスチャのスタイルが二箇所に割れ、片方だけ直す余地が入る     |

## 帰結

- スモークの spec は自足の検査だけを持ち、画面の操作か配置を見る spec は E2E の置き場へ足す
- 公開画面の配置を変える PR は、E2E の三つの条件で部品の矩形が重ならないことを保つ
- CI と、リモートのコンテナの準備のスクリプトが入れるブラウザ（Chromium と WebKit）は変わらない
- スモークと E2E が緑でも、地図が正しく描かれていることと、iPhone の実機でタッチが効くことの保証にはならない

## 覆る条件

- E2E の実行時間が、手元で区切りごとに回せない長さになったとき（E2E を CI だけで回すかを選び直す）
- 操作と配置の検査が、外部への通信を遮断したままでは書けなくなったとき（実タイルを叩くか、タイルのフィクスチャを持つかを選び直す）
- Playwright が iOS のタッチの経路をヘッドレスで回せるようになったとき（iPhone の条件を、そちらへ替えるかを選び直す。20261112-smoke-mobile-webkit-chromium から変わらない）
- 公開画面のスマホの対象から、iPhone か Android のどちらかを外すとき（20261112-smoke-mobile-webkit-chromium から変わらない）
