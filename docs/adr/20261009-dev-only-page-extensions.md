# 管理画面は公開サイトと同じ Next.js のアプリに置き、開発サーバでだけ読む拡張子で成果物から外す

- **状態**: 採用
- **決定日**: 2026-10-09（#110）
- **関係する ADR**: 20260902-local-only-admin（手元でだけ動く管理画面。決定 5 の答え）、20260714-nextjs-static-export（static export）

## 文脈

20260902-local-only-admin は、管理画面を手元でだけ動かし、公開サイトの成果物（`out/`）に含めないと決めた。
実装の形は、`next dev` でだけ立つページか `web/scripts/` の別プロセスかを決めずに #110 へ残した。
条件は「成果物に混ざらないことを検査で示せる」の一点である。

## 決定

- 管理画面のページと Route Handler は、公開サイトと同じ Next.js のアプリの中に、開発サーバでだけページとして読む拡張子で置く（決定時点では `page.dev.tsx`・`route.dev.ts`）
- 開発サーバかどうかは、Next の設定の関数が受けるフェーズが `PHASE_DEVELOPMENT_SERVER` かで判定し、そのときだけ `pageExtensions` に開発用の拡張子を足す
- 成果物に混ざらないことは、スモークが `out/` を走査して示す

現況は `web/next.config.ts` と `docs/HARNESS.md` が持つ。

## 理由

公開の地図と同じ道具（MapLibre の設定・`catalog/` のスキーマ・`catalog/` を読む関数・basePath）を、管理画面が import でそのまま使える。
2026-09-15 の実験で、`next dev` では管理画面のページと POST を受ける Route Handler が 200 を返し、`next build` の `out/` に `admin` を名に含むファイルは 0 件だった。

| 案 | 採らなかった理由 |
|---|---|
| `web/scripts/` の別プロセス（素の node の HTTP サーバと地図の画面） | 地図の描画・worker の配り方・スキーマの読み込みを、Next の外でもう一度組むことになる |
| `NODE_ENV` が `development` かで判定する | `NODE_ENV=development` を付けて `next build` を打つと、管理画面が成果物に入る |

## 帰結

- 開発サーバでだけ立てるファイルは、拡張子で見分ける
  普通の拡張子で置いたページは成果物に入る
- 開発用の拡張子のファイルも `.tsx`・`.ts` で終わるので、型検査・lint・単体テストの対象に入る
- スモークが、`out/` に名前に `admin` を含むファイルとディレクトリが無いことを見る
- 管理画面に足す機能（代表点の新設と位置なし化・シリーズの文字欄の編集）も同じ拡張子で置く

## 覆る条件

Next.js がフェーズごとに `pageExtensions` を切り替える設定を受け付けなくなったとき。
公開サイトが static export をやめてサーバを持ち、ページを公開するかを別の手段で分けられるようになったとき。
