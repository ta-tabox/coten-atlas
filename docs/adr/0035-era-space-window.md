# 0035. 現在窓の幅は era 空間の位置で決め、`"present"` の右端は呼び出し元が渡す現在年にする

- **状態**: 採用
- **決定日**: 2026-09-07（#136）
- **関係する ADR**: 0019・0031

## 文脈

スライダーの UI は「位置 → 年 → opacity」の写像が決まらないと書けない。

`ARCHITECTURE.md`「時系列（era）モデル」は現在窓の幅を**未決定**と書き、[0019](0019-era-open-end.md)（終わっていない era の `end` には印を置く）は `"present"` の右端に当たる年を「S4 が決める」と書いている。
窓の幅と右端の年はどちらも描画の手前にある値で、決まらないと重なり率が決まらず、opacity も決まらない。

スライダーが指すのは 1 点だが、シリーズは `timeRange` という幅を持つので、点と幅は直接比べられない。
点の周りに幅を持つ窓を取って重なり率（0..1）を求め、重なり率をイージングに通した値を opacity にする。

## 決定

**現在窓の幅は era 空間の位置で決め、その両端を年へ変換してから `timeRange` と比べる。**

1. 窓の幅は era 空間の **1 区間の幅に対する割合**で持つ（`WINDOW_WIDTH_IN_ERAS = 0.5`）。
   位置の上で幅を決め、その両端をそれぞれ年へ変換する
2. 窓は `timeRange` と同じ**両端を含む閉区間**で持つ。
   era の半開区間（`end` を含まない）は位置から年への変換の中で閉じ、変換より後ろでは端の扱いを 1 つにする
3. 重なり率は年数の比で、**分母は窓と `timeRange` の短い方**を取る。
   閉区間なので年数は `end - start + 1` で数える
4. 重なり率から opacity へは **smoothstep**（`r² (3 - 2r)`）を通す
5. **`"present"` の右端は現在年**にする。
   値は `positionToYear` と `currentWindow` の引数で受け取り、時計を読むのは `presentEndOf(now)` の 1 箇所に限る
6. 置き場は `web/src/lib/era/` で（[0031](0031-lib-layout-by-concern.md)）、`space.ts`（位置 → 年）と `window.ts`（年 → 濃淡）に割る。
   `node:fs`・React・MapLibre を import しない

## 理由

**幅を era 空間の位置で決めたのは、年で決めると era ごとに見え方が桁違いになるため。**
先史は 9200 年幅、19 世紀は 100 年幅なので、両者の間では 92 倍違う。
幅を年で固定すると、先史では窓がほぼ点になり、19 世紀では区間を丸ごと覆う。

**分母を年数の短い方にしたのは、窓と `timeRange` のどちらが短いかがシリーズごとに入れ替わるため。**
1 年の出来事を扱うシリーズと、era を丸ごと覆うシリーズが同じ地図に載る。
どちらも現在窓が指す時代のシリーズであることに変わりは無いので、一方が他方を完全に含むときは 1.0 を返す形にする。

**右端を現在年にしたのは、目盛りが動く条件を減らすため。**
シリーズの最大 `timeRange.end` から決めると、S7 でシリーズを足していく間じゅう同じ操作が別の年を指し続ける。
現在年なら動くのは年に一度で、`catalog/eras.json` は 0019 の通り人間が明示的に変えるまで動かない。

**時計を変換の外へ出したのは、同じ引数へ常に同じ年を返すため。**
変換の中で現在年を読むと、戻り値が呼び出しごとに変わりうるので、テストが実行時刻に依存する。

### 採らなかった案

- **窓の幅を年で固定する（例: 前後 50 年）。**
  era を跨いでも幅が変わらないので、年で考える読み手には分かりやすい。
  ただし先史と 19 世紀で 92 倍の差がそのまま見え方の差になり、スライダーを均等に動かしても濃淡の出方が区間ごとに変わる
- **窓の幅を「その位置が居る era の幅の何割」として年で計算する。**
  区間内では上の決定と同じ年数になる。
  ただし era を跨ぐ位置で窓の幅が不連続に変わるので、境目を通過する瞬間だけ濃淡が不連続に変わる。
  位置の上で幅を決めて両端を変換すれば、境目を跨ぐ窓は前後の era の刻みを半分ずつ持つ形で連続する
- **分母を窓に固定する。**
  「窓のうちどれだけがそのシリーズか」という読み方になる。
  ただし 1 年のシリーズは窓の年数の逆数までしか上がらないので、スライダーがその年を指しても薄いまま残る
- **分母を `timeRange` に固定する。**
  「そのシリーズのうちどれだけが窓に入ったか」になり、短いシリーズは 1.0 に達する。
  ただし era を丸ごと覆うシリーズは窓をどれだけ覆っても薄いままで、`timeRange` の長さが濃さの上限を決めてしまう
- **重なり率をそのまま opacity にする。**
  変換が 1 段減る。
  ただし窓の端で傾きが不連続になるので、スライダーを動かすとシリーズが現れる瞬間と消える瞬間だけ濃さの変化が速くなる
- **右端をシリーズの最大 `timeRange.end` から決める。**
  空の区間が原理的に出ない（0019 が挙げた案）。
  ただし S7 でシリーズを足すたびに目盛りが動く
- **右端を `catalog/eras.json` へ固定値で書く。**
  写像へ渡す値が要らなくなる。
  ただし 0019 が拒否した形（終わっていない時代に終わりの年を書く）へ戻る

## 帰結

- 位置から opacity までの写像が UI を持たない層で閉じた。
  `web/src/lib/era/` は `node:fs`・React・MapLibre を import しないので、スライダーの実装は `web/src/lib/era/` の 4 つの関数を呼ぶだけになる
- `circle-opacity` への配線はこの ADR の決定に含まれない。
  `web/src/lib/map/series-layer.ts` の paint を差し替えるのはスライダーを実装する issue で、`web/src/lib/era/` は 0..1 の数値を返すまでを担当する
- era の刻みを見直すと、窓が跨る年数も一緒に変わる。
  幅を割合で持つので、区間を細かく割れば窓も細かくなる
- 現在年を渡すのは `web/src/lib/era/` の呼び出し元になる。
  static export のビルド時に確定させるか、ブラウザで `presentEndOf(new Date())` を読むかは、スライダーを実装する issue が決める
- 0019 の「右端に当たる年は描画のときに決まる」はそのまま保つ。
  `presentEnd` を引数で受け取る形が扱いにくいとは分からなかったので、supersede はしない
- `ARCHITECTURE.md`「時系列（era）モデル」の「現在窓の幅は未決定」はこの ADR が埋める。
  `ARCHITECTURE.md` の書き換えは並行して走る作業との衝突を避けるため、#136（S4: era 空間の写像と現在窓を純関数へ落とす）では行わない

## 覆る条件

実際に描いてみて、1 区間の半分という幅が広すぎるか狭すぎると分かったとき。
割合の値を動かすだけなら `WINDOW_WIDTH_IN_ERAS` の変更で済むので、覆るのは幅を era 空間の位置で決めること自体をやめるときに限る。

スライダーが era 空間でなく年を等間隔に刻むようになったとき。
位置と年が線形に対応するなら、幅を年で固定しても era ごとの差は出ない。

終わっていない era が複数要るようになったとき（0019 と同じ）。
右端に当たる年が 1 つでは足りなくなる。
