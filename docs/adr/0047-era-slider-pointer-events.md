# 0047. era スライダーのポインタの操作はトラックの要素のポインタのイベントで受け、`<input type="range">` にはキーボードの操作と読み上げだけを任せる

- **状態**: 採用
- **決定日**: 2026-09-15（#241）
- **関係する ADR**: 0043（目盛りとキーボードの操作）、0022（地図の上に載せるもの）

## 文脈

iPhone の Safari で era スライダーのつまみの上から横へスワイプすると、現在窓が動かなかった。
タップでは現在窓が動いた。

決定の時点のスライダーは、トラックを透明にした `<input type="range">` を era のセルの列に重ね、マウス・タッチ・キーボードの操作をすべてブラウザ既定の挙動に任せていた。
つまみは幅 4px の縦棒だった。

症状は手元で再現しなかった。
Playwright の WebKit（macOS の上で動くビルド）にはタッチのスワイプを送る手段が無く（`Touchscreen` の操作は `tap` だけで、`new Touch()` は throw する）、Chromium では CDP で送ったタッチのスワイプでつまみが動いた。
手元に iOS Simulator も無い。
iOS の WebKit が `<input type="range">` のタッチをどう扱うかを、手元では確かめられない。

## 決定

**era スライダーのポインタ（マウス・指・ペン）の操作は、era のセルの列と `<input type="range">` を包むトラックの要素が受けるポインタのイベントから位置を求める。`<input type="range">` はキーボードの操作と読み上げのために残し、ポインタのイベントを受けさせない。**

| 論点 | 決定 |
|---|---|
| ポインタを受ける要素 | トラックの要素。`touch-action: none` を指定する |
| 座標から位置への変換 | トラックの矩形に対するポインタの横の割合を、`<input type="range">` と同じ目盛りへ丸める。DOM を読まない純関数に置き、単体テストを付ける（決定の時点では `web/src/lib/era/pointer.ts` の `clientXToPosition`。現況はコードが持つ） |
| 押している間 | 押したポインタを `setPointerCapture` し、同じ `pointerId` の移動だけを位置に反映する。主でないポインタと副ボタンは無視する |
| `<input type="range">` | `pointer-events: none`。キーボードの操作は 0043 のとおりブラウザ既定の挙動に任せる |
| 押したときのフォーカス | `<input type="range">` へ移す。フォーカスの枠はキーボードでフォーカスを移したときだけ出す |

## 理由

- **ポインタのイベントから位置を求める** — iOS の WebKit の `<input type="range">` のタッチの処理を経由しないので、その処理がスワイプを扱わない原因を特定できなくても、トラックのどこから始めたスワイプでも位置が動く
- **座標から位置への変換を純関数に置く** — jsdom はレイアウトを持たないので、矩形を受け取って位置を返す関数に分けると、ポインタの操作で位置が変わることを単体テストで確かめられる
- **`touch-action: none`** — ブラウザがトラックの上のタッチをスクロールや拡大に使うと `pointercancel` が届き、位置が指に追従しなくなる
- **目盛りへ丸める** — ポインタで動かした位置とキーボードで動かした位置を、同じ `<input type="range">` の値で表せる
- **`<input type="range">` を残す** — キーボードの操作と `aria-valuetext` の読み上げを、ブラウザ既定の挙動のまま保てる
- **押したときにフォーカスを移す** — 押した後に矢印キーで続けて動かせる

採らなかった案。

- つまみの透明な幅を広げ、ポインタの操作を `<input type="range">` に任せ続ける ／ iOS の WebKit はつまみの矩形の内側で始まったタッチだけをドラッグにする、という確かめていない推測に依存し、直ったかを実機でしか判定できない。つまみの中心が動ける範囲も両端からつまみの半幅ずつ狭まり、現在窓の帯の中心とずれる
- `<input type="range">` にポインタのイベントを受けさせたまま、トラックの要素でも位置を求める ／ 同じ操作に `<input type="range">` の既定の処理とトラックの要素の処理が両方応じうるので、位置を決める処理が一つに定まらない

## 帰結

- トラックの上のタッチでは、ページのスクロールと拡大が始まらない。地図の canvas の上のタッチは変わらない
- トラックを押すと、押した座標の位置へ動く。つまみの上を押したときも、つまみの中心と押した座標の差（最大でつまみの半幅）だけ動く
- ポインタの操作で位置が変わることは jsdom の単体テストが確かめる。iPhone の Safari の実機でスワイプに追従するかは人間が確かめる
- `<input type="range">` が `pointer-events: none` なので、VoiceOver で画面に触れて要素を探す操作がスライダーに届くかは、ブラウザがアクセシビリティのヒットテストで `pointer-events` を見るかに依存する。決定の時点では確かめていない

## 覆る条件

iPhone の Safari の実機で、トラックの上のスワイプで位置が動かないと分かったとき（ポインタのイベントの経路でも動かない原因を探し直す）。
支援技術で `<input type="range">` に触れて操作できないと分かったとき（`pointer-events: none` をやめ、`<input type="range">` の既定のポインタの処理を別の手段で止める）。
モバイルでの振る舞いを決める S8 の精緻化で、スライダーが `<input type="range">` を重ねる形でなくなったとき。
