# 0036. 配信後のスモークを持つ（ブラウザを立てず、配信物への到達だけを見る）

- **状態**: 採用
- **決定日**: 2026-09-07
- **関係する ADR**: 0014、0009、0007、0013

## 文脈

`pnpm check` の L4 スモークが相手にするのは手元の `out/` で、それを配信するのは `web/scripts/smoke.ts` が立てるサーバである（[ADR-0014](0014-e2e-offline-smoke.md)）。
そのサーバは `BASE_PATH` を読んで同じ接頭辞の下へ置くので、アプリが焼いた接頭辞と検査が配信する接頭辞は同じ定数から来る。
二つが食い違うことが原理的に起きない組み合わせなので、接頭辞そのものが配信先と合っていない形は L4 が緑のまま通る。

`deploy.yml` が見るのは `next build` の成功と artifact のアップロードまでで、配信された実物を機械が開く口は無い。
`docs/ROADMAP.md`「完了条件の閾値」の 1（公開 URL で地図アプリが動作する）を機械で守る口が無い、と言っても同じことを指す。

#127（配信先の接頭辞をアプリのソースから追い出す）はこの食い違いを構成の側で防ごうとしており、issue 本文が「手元では通って本番だけ落ちる」が場所を変えて戻ってくる形を名指している。
構成で防ぐことと、防げたかを別の出所から確かめることは別なので、接頭辞の出所を動かす側と同じ層に検査を置いても意味を持たない。

## 決定

配信後のスモークを持つ。
置き場は `deploy.yml` の deploy ジョブの後段で、`actions/deploy-pages` の次のステップに置く。

見るのは一点だけである。

> 配信されたページが名指している参照へ、そのページが配信された URL から到達できるか。

手順は次のとおり。

1. `steps.deployment.outputs.page_url` を取り、そこを開く
2. 返った HTML から `src` / `href` の絶対パスを集める
3. 集めた各パスを同じオリジンから引き、4xx / 5xx が無いことを見る

取り出しが壊れると検査が黙って無検査になり、緑と区別が付かなくなるので、参照が 1 件も取れなければ赤にする。

**ブラウザを立てない。** canvas も実行時エラーも見ない。

`docs/HARNESS.md`「1. 検証の層構造」の層番号を与えず、`pnpm check` にも入れない。
配信の後にしか走らないので close の判定には使えず、「これが緑なら閉じてよい」と言える口は `pnpm check` のまま一本である（[ADR-0009](0009-pnpm-check.md)）。

`web/tests/smoke/` と `playwright.config.ts` の `smoke` project は動かさない。

## 理由

L4 が原理的に見られないものは接頭辞が配信先と合っているかの一点で、それはブラウザを立てなくても分かる。
ページが自分で名指している参照を、そのページが実際に配信された URL から引けるかを見れば足りる。

canvas を見ても増えるものが無い。
canvas が立つかは「配信物へ到達できるか」と「配信物の中身が正しいか」の両方で決まり、後者は L4 が同じバイト列をブラウザで開いて既に見ている。
配信で新しく入る変数は到達性だけなので、そこだけを見る。

**ブラウザを立てると外部を一つ抱え込む。**
地図を描かせるにはタイルサーバが要るので、実タイルを引けば配信の経路が `tiles.openfreemap.org` の可用性で赤くなり、`docs/HARNESS.md`「6. 意図的にやらないこと」が避けている形が配信の側から入る。
フィクスチャで返せば、それは L4 のスモークを別のホストへ向けただけのものにしかならない。
どちらを選んでも、ブラウザを立てた分の対価が出てこない。

このプロジェクトは終わるので、恒久運用を前提にした外形監視にしない（`CLAUDE.md` 冒頭）。
走るのは配信の回だけで、時刻で起きる run は持たない。

### 採らなかった案

- **持たない（人間が公開 URL を踏むので足りる）。** 配信の頻度は低く、ポートフォリオとして人間が開く前提もあるので、成り立つ読みではある。採らないのは、#127 が接頭辞の出所を動かす予定で、それが外したときの形が「機械はどこも緑のまま配信だけが白紙」だから。気付くのが人間の開いた回になり、それが公開後のいつになるかを決められない
- **ブラウザで開いて canvas まで見る。** #132（配信された実物を機械が一度も開いていない）の当初の素描がこれで、遮断版と同じ三点を実物へ当てる。採らないのは上の理由による。Chromium 356MB を配信の経路へ持ち込む対価に見合うものが、到達性の先に無い。採る条件は、到達性が緑のまま実物だけが壊れる形が実際に事故として出たとき
- **`workflow_run` で追う別ワークフローにする。** 配信と検査で関心が分かれるが、`page_url` はワークフローを跨がないので、URL を書き下ろすか API で引き直すことになる。#132 が避けたい「出所が二つ」がそこで戻る
- **deploy ジョブと別のジョブにする。** 配信の成否と検査の成否がジョブの粒度で分かれるが、URL をジョブの出力へ通す配線と、`curl` 一本のためのランナーが増える。deploy ジョブは checkout を持たず `permissions` も `pages: write` と `id-token: write` だけなので、ステップとして置けば増えるものが無い

## 帰結

- 配信の run が赤くなりうる先が一つ増える。配信そのものは終わった後なので、赤は「配れたが読めない」の意味になる
- **GitHub Pages の可用性と伝播で赤くなる余地が入る。** ページの取得には再試行を掛けるが、CDN が古い版を返し続ける形までは吸収しない
- 検査の対象は HTML が名指す参照に限る。MapLibre の worker は実行時に組み立てる URL なので入らない（在り処は [ADR-0013](0013-maplibre-worker-self-hosted.md) の `web/tests/map-worker-assets.test.ts`、到達性は L4 が見る）
- `deploy.yml` にシェルが入る。`lint-comments.ts` が見るのは `.ts` / `.tsx` / `.mts` なので、ここの書き方を機械は守らない
- 配信後の検査が緑でも、地図が正しく描かれている保証にはならない。絵の判定は人間の目視のまま残る

## 覆る条件

接頭辞の出所が一つに定まり、食い違う形が構成上作れなくなったとき。
#127 がそこまで到達したら、この検査が守っているものが残っているかを見て、畳むかを選び直す。

配信の経路が GitHub Pages の伝播で繰り返し赤くなり、赤が「配れたが読めない」の意味を失ったとき。
再試行を伸ばすか、検査を配信の run の外へ出すかを選び直す。
