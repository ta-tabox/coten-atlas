# 0036. 配信の直後に到達テストを走らせる（ブラウザを立てず、`src`・`href` のパスへの到達だけを検証する）

- **状態**: 採用
- **決定日**: 2026-09-07（#132）
- **関係する ADR**: 0007（GitHub Pages で配信する）、0009（判定を `pnpm check` の一本にする）、0013（MapLibre の worker をこのリポジトリが配る）、0014（外部を遮断したスモーク 1 枚に限る）

## 文脈

`pnpm check` の L4 スモーク（[0014](0014-e2e-offline-smoke.md)）は、`web/scripts/smoke.ts` が立てるサーバで `out/` を `BASE_PATH` の下へ配信して開く。
アプリがビルド時に埋める接頭辞と、スモークが配信する接頭辞は同じ定数 `BASE_PATH` から来るので、二つは食い違わない。
そのため、`BASE_PATH` そのものが配信先の URL と合っていない形は L4 を通過する。

`deploy.yml` が検証するのは `next build` の成功と artifact のアップロードまでで、配信された実物を取得する検査は無い。

## 決定

**`deploy.yml` の deploy ジョブで、`actions/deploy-pages` の次のステップとして到達テストを走らせる。**

| 論点 | 決定 |
|---|---|
| 検証すること | `src`・`href` のパス（取得した HTML の `src`・`href` 属性のうち `/` で始まる値）へ、そのページのオリジンから到達できるか |
| 対象の URL | `steps.deployment.outputs.page_url`。ワークフローに書き下ろさない |
| 失敗にする条件 | ページを取得できない・`src`・`href` のパスが 0 件・パスのどれかが 4xx か 5xx |
| ブラウザ | 立てない。canvas と実行時エラーは検証しない |
| `pnpm check` との関係 | 連鎖に入れず、層の番号も与えない。close してよいかの判定は `pnpm check` のまま |
| L4 スモーク | `web/tests/smoke/` と `web/playwright.config.ts` の `smoke` project は変えない |
| 実装 | `run:` のシェル。checkout を足さない |

## 理由

- **到達性だけを検証する** — canvas と実行時エラーは L4 が同じバイト列をブラウザで開いて検証しているので、配信で増える条件は到達性だけである
- **パスを HTML から集める** — 接頭辞をスクリプトに書くと、検証する接頭辞と配信する接頭辞の出所が二つになり、食い違いを検出できない
- **パス 0 件を失敗にする** — パスを集める処理が壊れると 0 件になり、何も検証しないまま成功する
- **close の判定に使わない** — 到達テストは main へ入った後に走るので、close の判定に間に合わない
- **deploy ジョブのステップに置く** — deploy ジョブは checkout を持たず、`permissions` も `pages: write` と `id-token: write` だけなので、ステップを足しても checkout も権限も増えない
- **時刻で起動する run を持たない** — このプロジェクトは終わる（`CLAUDE.md` 冒頭）ので、恒久的な外形監視にしない

### 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 持たない（人間が公開 URL を開けば足りる） | #127（配信先の接頭辞をアプリのソースから追い出す）が接頭辞の出所を動かして食い違いが入ると、`pnpm check` が緑のまま配信先で地図が描画されず、人間が開くまで検出されない |
| ブラウザで開いて canvas まで検証する | 地図の描画にタイルサーバが要る。実タイルを取得すると配信の経路が `tiles.openfreemap.org` の可用性で失敗し、フィクスチャを返すと L4 と同じ検証になる |
| `workflow_run` で起動する別ワークフローにする | `page_url` がワークフローをまたいで渡らず、URL を書き下ろすか API で取得し直すことになる |
| deploy ジョブと別のジョブにする | `page_url` をジョブの出力へ渡す配線と、`curl` を走らせるランナーが増える |

## 帰結

- 配信の run が失敗する条件が増える。失敗は「配信したが `src`・`href` のパスへ到達できない」を意味する
- GitHub Pages の可用性と伝播の遅れで失敗しうる。ページの取得は再試行するが、CDN が古い版を返し続ける状態までは待たない
- MapLibre の worker は実行時に URL を組み立てるので、`src`・`href` のパスに入らず、到達テストの対象外である。worker のファイルが在るかは [0013](0013-maplibre-worker-self-hosted.md) の `web/tests/map-worker-assets.test.ts`、到達できるかは L4 が検証する
- `lint-comments.ts` は `.ts` / `.tsx` / `.mts` だけを検査するので、`deploy.yml` のシェルのコメントを機械は検査しない
- 地図が正しく描画されているかの判定は人間の目視に残る
- `docs/HARNESS.md`「到達テスト」に現況を書く

## 覆る条件

#127 が接頭辞の出所を一つに定め、食い違いを構成上作れなくしたとき（到達テストをやめるかを選び直す）。
到達性が緑のまま、配信先で地図が描画されない事故が起きたとき（ブラウザで canvas まで検証するかを選び直す）。
伝播の遅れで失敗が繰り返され、失敗が「`src`・`href` のパスへ到達できない」を意味しなくなったとき（再試行を増やすか、到達テストを配信の run の外へ出すかを選び直す）。
