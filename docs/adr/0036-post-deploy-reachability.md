# 0036. 配信後のスモークを持つ（ブラウザを立てず、配信物への到達だけを見る）

- **状態**: 採用
- **決定日**: 2026-09-07（#132）
- **関係する ADR**: 0007（GitHub Pages で配信する）、0009（判定を `pnpm check` の一本にする）、0013（MapLibre の worker をこのリポジトリが配る）、0014（外部を遮断したスモーク 1 枚に限る）

## 文脈

`pnpm check` の L4 スモーク（[0014](0014-e2e-offline-smoke.md)）は、`web/scripts/smoke.ts` が立てるサーバで `out/` を `BASE_PATH` の下へ配信して開く。
アプリがビルド時に埋める接頭辞と、スモークが配信する接頭辞は同じ定数 `BASE_PATH` から来るので、二つは食い違わない。
そのため、`BASE_PATH` そのものが配信先の URL と合っていない形は L4 を通過する。

`deploy.yml` が検証するのは `next build` の成功と artifact のアップロードまでで、配信された実物を取得する検査は無い。

#127（配信先の接頭辞をアプリのソースから追い出す）は接頭辞の出所を動かす予定で、動かした後に食い違いが入る余地がある。

## 決定

**`deploy.yml` の deploy ジョブで、`actions/deploy-pages` の次のステップとして配信後のスモークを走らせる。**

| 論点 | 決定 |
|---|---|
| 検証すること | 配信されたページが名指す参照へ、そのページが配信された URL から到達できるか |
| 対象の URL | `steps.deployment.outputs.page_url`。ワークフローに書き下ろさない |
| 集める参照 | 取得した HTML の `src` / `href` のうち `/` で始まるもの |
| 失敗にする条件 | ページを取得できない・参照が 0 件・参照のどれかが 4xx か 5xx |
| ブラウザ | 立てない。canvas と実行時エラーは検証しない |
| `pnpm check` との関係 | 連鎖に入れず、層の番号も与えない。close してよいかの判定は `pnpm check` のまま |
| L4 スモーク | `web/tests/smoke/` と `web/playwright.config.ts` の `smoke` project は変えない |
| 実装 | `run:` のシェル。checkout を足さない |

## 理由

- **到達性だけを検証する** — L4 が同じバイト列をブラウザで開いて中身を検証しているので、配信で増える条件は到達性だけである
- **ブラウザを立てない** — 地図を描画させるにはタイルサーバが要る。実タイルを取得すると配信の経路が `tiles.openfreemap.org` の可用性で失敗し、フィクスチャを返すと L4 と同じ検証になる
- **参照を HTML から集める** — 接頭辞をスクリプトに書くと、検証する接頭辞と配信する接頭辞の出所が二つになり、食い違いを検出できない
- **参照 0 件を失敗にする** — 参照を集める処理が壊れると 0 件になり、何も検証しないまま成功する
- **deploy ジョブのステップに置く** — `page_url` を同じジョブの中で読める。deploy ジョブは checkout を持たず、`permissions` も `pages: write` と `id-token: write` だけなので、ステップを足しても権限は増えない
- **恒久的な外形監視にしない** — このプロジェクトは終わる（`CLAUDE.md` 冒頭）。走るのは配信の回だけで、時刻で起動する run を持たない

採らなかった案:

- **持たない（人間が公開 URL を開けば足りる）** — 検査の実装が要らない。ただし #127 が接頭辞の出所を動かして食い違いが入ると、`pnpm check` が緑のまま配信先で地図が描画されず、人間が開くまで検出されない
- **ブラウザで開いて canvas まで検証する** — L4 と同じ三点を実物に当てられる。ただし Chromium 356MB を配信の経路へ入れても、到達性の先に増える検証が無い。採る条件は、到達性が緑のまま実物だけが壊れる事故が起きたとき
- **`workflow_run` で起動する別ワークフローにする** — 配信と検証のワークフローが分かれる。ただし `page_url` はワークフローをまたいで渡らず、URL を書き下ろすか API で取得し直すことになる
- **deploy ジョブと別のジョブにする** — 配信と検証の成否がジョブ単位で分かれる。ただし `page_url` をジョブの出力へ渡す配線と、`curl` を走らせるランナーが増える

## 帰結

- 配信の run が失敗する条件が増える。失敗は配信が完了した後に出るので、「配信したが参照へ到達できない」を意味する
- GitHub Pages の可用性と伝播の遅れで失敗しうる。ページの取得は再試行するが、CDN が古い版を返し続ける状態までは待たない
- MapLibre の worker は実行時に URL を組み立てるので、HTML の参照に入らず、このスモークの対象外である。worker のファイルが在るかは [0013](0013-maplibre-worker-self-hosted.md) の `web/tests/map-worker-assets.test.ts`、到達できるかは L4 が検証する
- `lint-comments.ts` は `.ts` / `.tsx` / `.mts` だけを検査するので、`deploy.yml` のシェルのコメントを機械は検査しない
- 緑でも、地図が正しく描画される保証にはならない。描画の判定は人間の目視のまま残る

## 覆る条件

#127 が接頭辞の出所を一つに定め、食い違いを構成上作れなくしたとき（このスモークをやめるかを選び直す）。
伝播の遅れで失敗が繰り返され、失敗が「参照へ到達できない」を意味しなくなったとき（再試行を増やすか、スモークを配信の run の外へ出すかを選び直す）。
