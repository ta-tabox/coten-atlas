# 0038. 現在窓の幅は era 空間の位置で決め、`"present"` の右端は呼び出し元が渡す現在年にする

- **状態**: 採用
- **決定日**: 2026-09-07（#136）
- **関係する ADR**: 0019（終わっていない era の印）、0031（`lib/` を関心ごとのディレクトリで割る）

## 文脈

era スライダーは位置を 1 点で指し、シリーズの `timeRange` は幅を持つので、位置の周りに幅を持つ現在窓を取り、窓と `timeRange` の重なり率（0..1）からシリーズの表示 opacity を求める。
era 空間は `catalog/eras.json` の各区間を等幅に並べた 0..1 の数直線で、区間の年幅は先史が 9200 年、19 世紀が 100 年と 92 倍違う。

この計算に要る値のうち 2 つが決まっていなかった。
`ARCHITECTURE.md`「時系列（era）モデル」は現在窓の幅を未決定と書き、[0019](0019-era-open-end.md) は `end` が `"present"` の era の右端に当たる年を S4 に委ねていた。

## 決定

**現在窓の幅は era 空間の位置で決め、窓の両端を年へ変換してから `timeRange` と比べる。**

| 論点 | 決定 |
|---|---|
| 窓の幅 | era 空間の 1 区間の幅に対する割合で持つ（`WINDOW_WIDTH_IN_ERAS = 0.5`）。位置の上で幅を決め、窓の両端をそれぞれ年へ変換する |
| 区間の端 | 窓は `timeRange` と同じく両端を含む閉区間で扱う。era の半開区間（`end` を含まない）を扱うのは `positionToYear` だけにする |
| 重なり率 | 重なる年数を、窓と `timeRange` のうち短い方の年数で割る。年数は `end - start + 1` で数える |
| 重なり率から opacity | smoothstep（`r² (3 - 2r)`）を通す |
| `"present"` の右端 | 現在年。`positionToYear` と `currentWindow` が `presentEnd` で受け取り、時計を読むのは `presentEndOf(now)` だけにする |
| 置き場 | `web/src/lib/era/`。`space.ts`（位置 → 年）と `window.ts`（窓 → opacity）に分け、`node:fs`・React・MapLibre を import しない |

## 理由

- **幅を era 空間の位置で決める** — スライダーを同じ量動かしたときに、窓が区間の中で占める割合が区間の年幅によらず揃う
- **窓を閉区間で扱う** — `timeRange` が閉区間なので、端の扱いを揃えると重なり率の計算に半開区間の補正が要らない
- **右端を現在年にする** — 現在年が変わるのは年に一度で、`catalog/eras.json` は 0019 のとおり人間が書き換えるまで動かない

採らなかった案:

- **窓の幅を年で固定する（例: 前後 50 年）** — era を跨いでも窓の年数が変わらない。ただし先史では窓がほぼ点になり、19 世紀では区間を丸ごと覆う
- **窓の幅を「位置が属する era の年幅の割合」として年で足し引きする** — 区間の中では採った決定と同じ年数になる。ただし era の境目で窓の年数が不連続に変わり、境目を通過する瞬間だけ濃さが不連続に変わる
- **重なり率の分母を窓の年数にする** — 「窓のうちどれだけがそのシリーズか」と読める。ただし 1 年のシリーズは窓の年数の逆数までしか上がらず、スライダーがその年を指しても薄い
- **重なり率の分母を `timeRange` の年数にする** — 短いシリーズは 1.0 に達する。ただし era を丸ごと覆うシリーズは窓をどれだけ覆っても薄い
- **重なり率をそのまま opacity にする** — 変換が 1 段減る。ただし窓の端で傾きが不連続になり、シリーズが窓へ入る瞬間と出る瞬間だけ濃さの変化が速くなる
- **右端をシリーズの最大 `timeRange.end` にする** — 空の区間が出ない（0019 が挙げた案）。ただし S7 でシリーズを足すたびに目盛りが動き、同じ位置が別の年を指す
- **右端を `catalog/eras.json` に年で書く** — 変換が `catalog/eras.json` だけで閉じる。ただし 0019 が拒否した「終わっていない時代に終わりの年を書く」形に戻る
- **`positionToYear` の中で現在年を読む** — 呼び出し元が `presentEnd` を用意しなくてよい。ただし同じ引数への戻り値が呼び出しごとに変わりうるので、テストが実行時刻に依存する

## 帰結

- スライダーの実装は `web/src/lib/era/` の関数を呼んで位置から opacity までを得る。`web/src/lib/map/series-layer.ts` の `circle-opacity` へ配線するのはスライダーを実装する issue である
- 重なり率の分母が短い方なので、窓より長いシリーズは、窓がシリーズの期間の内側にある間 1.0 を返し続ける。お金の歴史（前600〜2020）は、スライダーが古代の半ばから戦後までを指す間、表示 opacity が 1.0 のままになる。長いシリーズを他のシリーズより薄く描くかは、スライダーを実装する issue が `kind` ごとの濃さとの掛け合わせと合わせて決める
- `catalog/eras.json` の区間を割り直すと、窓が跨る年数も区間の年幅に合わせて変わる
- `presentEnd` に現在年を渡すのは呼び出し元である。static export のビルド時に確定させるか、ブラウザで `presentEndOf(new Date())` を読むかは、スライダーを実装する issue が決める
- 0019 の覆る条件「描画時に決める形が扱いにくいと分かったとき」には当たらないので、0019 を supersede しない
- `ARCHITECTURE.md`「時系列（era）モデル」の「現在窓の幅は未決定」と「決め方は S4」は、このレコードの決定へ書き換える必要がある

## 覆る条件

窓の幅を era 空間の位置で決める形では、描いた窓の広さが合わないと分かったとき（`WINDOW_WIDTH_IN_ERAS` の値を変えるだけなら覆らない）。
スライダーが年を等間隔に刻むようになったとき（位置と年が線形に対応し、年で幅を固定しても区間ごとの差が出ない）。
終わっていない era が 2 つ以上要るようになったとき（右端の年が 1 つでは足りない。0019 と同じ）。
