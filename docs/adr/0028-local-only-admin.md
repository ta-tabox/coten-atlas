# 0028. データを編集する管理画面は手元でだけ動かし、保存先は git のまま

- **状態**: 採用
- **決定日**: 2026-09-02（#108）
- **関係する ADR**: 0001（static export）、0005（データの二層分離）、0007（GitHub Pages）、0026（位置情報の段階分け）、0027（シリーズと事物の分離）

## 文脈

シリーズは 66 件あり、第一段階でも各シリーズの代表点を JSON へ手で書くのは無理だと判定した。
座標を地図の上で置いて保存する管理画面が要る。

0001 は static export で、`ARCHITECTURE.md` §7 は「ユーザ登録・コメント等の動的機能を持たない」と書いている。
管理画面を公開サイトの上に置くと、認証と DB とサーバが要り、0001 と 0007 が覆る。

このプロジェクトは個人のポートフォリオで、費用を抑える。
編集者は一人で、編集の頻度はシリーズが増える月に数回である。
DB を含む構成は別のポートフォリオ（toiito）が見せるので、この器で見せる必要は無い。
このプロジェクトは終わるので、運用を持ち込まない。

## 決定

1. **管理画面は手元でだけ動く。**
   `pnpm dev` か専用の開発コマンドで立ち、公開サイトの成果物（`out/`）に含まれない
2. **書き先は `data/` のファイルで、保存先は git のまま。**
   保存はコミットで確定する
3. **認証・DB・サーバを持たない。**
   公開サイトは static export のままで、0001 と 0007 は動かない
4. 書き込み口は書く前にスキーマと参照の検査を通し、通らない値を書かない
5. 実装の形（`next dev` でだけ立つページか、`web/scripts/` の別プロセスか）は #110 で確かめて決める。
   条件は「成果物に混ざらないことを検査で示せる」の一点
6. 第二段階の事物の編集も同じ口に載せる（#111）
7. 第二段階の精緻な図形は二つの口から入る。
   管理画面で地図の上に描くか、外部データを `web/scripts/` の取り込みスクリプトで `loci.geojson` の形へ変換するか。
   どちらも同じスキーマと参照の検査を通し、git に置く。
   取得元とライセンスの判断は #96 が持つ

## 理由

編集者が一人で頻度が低いので、git が保存先として足りる。
diff がレビューになり、履歴が戻せる。
費用がゼロで、終わるプロジェクトに認証・秘密情報・バックアップの運用が乗らない。

採らなかった案:

- **公開サイト上の管理画面**（無料枠の Vercel + Neon、Cloudflare Pages + D1 など） — どこからでも編集できる。
  ただし 0001 と 0007 が覆り、認証と秘密情報と DB のバックアップが残る。
  無料枠でも運用は消えない。
  ポートフォリオで DB 構成を見せる目的は toiito が担う
- **geojson.io や QGIS で座標を作り JSON へ貼る** — 道具は増えないが、シリーズとの紐づけと貼り付けが手作業に残る。
  無理だと判定した手編集と同じ
- **GitHub の contents API へ直接書く** — ブラウザだけで済む。
  ただしトークンの管理が要り、手元で動かすなら fs へ書くほうが短い

## 帰結

- `ARCHITECTURE.md` §7 の「動的機能を持たない」は「公開サイトに持たない」へ絞る
- スモークが `out/` に管理画面が無いことを見る（#110）
- `HARNESS.md` に管理画面の打ち方が 1 段落入る
- 管理画面が書いたファイルも `web/tests/data.test.ts` の検査対象で、書く口が二つあっても検査は一つ
- 取り込みスクリプトは `pnpm sync` と同じ「ビルド前のデータ更新」の側に居り、公開サイトの成果物にも実行時にも入らない。
  外部データを直接読む口を公開サイトに持たない点は 0001 と同じ

## 覆る条件

手元以外から編集したい実需が出たとき。
編集者が二人以上になったとき。
