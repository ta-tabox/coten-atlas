# 0011. コードは MIT、データは CC BY 4.0、番組由来の要素は範囲外と明記する

- **状態**: 採用
- **決定日**: 2026-08-27（#55）
- **関係する ADR**: 0005（データの二層分離）、0008（引用は題号に限る）

## 文脈

`gh repo view --json licenseInfo` は `null` を返す。
ライセンスの無い public リポジトリは著作権法の原則どおり全ての権利が留保された状態なので、読む人は再利用の可否を判断できない。
public 化は #10 で、決めずに public にすると、後から足すときには既に読まれた後になる。

このリポジトリは読み手を二つ同時に持つ。
転職ポートフォリオとして読む採用担当と、番組のリスナーで道具として使いうる人である。
加えて `data/` は ADR-0005 で人間キュレーションの層として分けてあり、コードとは性質が違う。
載せる番組由来の要素は ADR-0008 でシリーズ名とエピソードタイトルに限ってあり、これは自分の著作物ではない。

## 決定

三つを分けて決める。

1. **コードは MIT**。ルートに標準の `LICENSE` を置く。
2. **データは CC BY 4.0**。対象は `data/themes.geojson` と `data/eras.json` で、`data/episodes.json` は含めない。
3. **番組由来の要素は自分のライセンスの範囲外**。この限定は `LICENSE` 本文へは書かず、README・`/about`・`data/LICENSE` が持つ。

`LICENSE` 本文は標準の MIT を一字も変えない。

## 理由

**コードを MIT にした理由**: このリポジトリの価値はコードの独自性ではなく構成と判断の履歴にあるので、再利用条件は最短で伝わればよい。
採用担当にもリスナーにも同じ一枚で足りる。

採らなかった案:

- **Apache-2.0** — 特許ライセンスの明示と報復条項が主な利得だが、特許が絡む実装がこのリポジトリに無い。
  本文の長さだけが読み手の費用として残る。
  企業がコードを取り込む前提を強く意識する段になれば覆る
- **置かない** — 全権利留保を意図的に選ぶ道はあるが、GitHub 上では「決めていない」と同じ外形になる。
  決定が読み手に届かないので、決めた意味が消える

**データを分けた理由**: `themes.geojson` が持つ座標・年代・`summary`・`match` はこのリポジトリの独自価値の中心なので、コードと同じ扱いにすると帰属表示の要求ごと落ちる。
CC BY はオープンデータの慣行として広く読まれ、条件の読み取りに追加の説明が要らない。

採らなかった案:

- **分けない** — LICENSE 一枚で済むが、キュレーション成果が無条件に取り込まれる
- **CC BY-SA 4.0** — 派生への同条件要求は OSM 系のデータ文化に近いが、他所が取り込むハードルが上がる。
  このリポジトリは取り込まれて困るものではない
- **データも全権利留保** — コードとの温度差を README で説明する費用が、得られる保護に見合わない

`episodes.json` を対象から外したのは、これが RSS 由来で自分の著作物ではないため。
主張できるのは選択と配列の体系だけなので、まとめて CC BY と言い切ると過剰主張になる。

**限定を `LICENSE` の外に置いた理由**: 除外条項を本文へ書き足すと SPDX として MIT と識別されなくなり、`licenseInfo` が `NOASSERTION` に倒れうる。
番組由来の要素をどこで断るかは ADR-0008 の4点表記が既に場所を作っているので、置き場を新設せず README と `/about` へ一項足せる。

## 帰結

- ルートの `LICENSE`（MIT）はこの ADR と同じ PR で入る
- `data/LICENSE`（CC BY 4.0。対象と対象外を明記する）は #3（S2 のスキーマ）が持つ。
  `data/` の現物がそこで初めて生まれる（`eras.json`）
- README のライセンス節はこの ADR と同じ PR で入る。
  コードとデータで条件が違うこと、番組由来の要素が範囲外であることが読める
- `/about` の4点表記（ADR-0008）へ、番組由来の要素が自分のライセンスの範囲外である旨を一項足す。
  文言の現物は #62（S8 の出典・ライセンス表記）が持つ
- フッタは触らない。
  フッタが担うのは公式への導線と出典表記への到達で、表記の全文を持つのは `/about` である（`ARCHITECTURE.md`「4. UI 構成」）。
  ライセンスの適用範囲をフッタへも書くと、到達させる役目と全文を持つ役目が二重になる
- 依存の Next.js・React（MIT）と MapLibre（BSD-3-Clause）はいずれも寛容型なので、この決定と衝突しない

## 覆る条件

コードについては、企業がコードを取り込む前提が具体化し、特許条項が要ると判断したとき（Apache-2.0 へ）。
データについては、再利用の実例が出て帰属表示だけでは足りないと分かったとき。
番組由来の扱いについては、番組公式が第三者向けの利用規約を出したとき（ADR-0008 の覆る条件と同じ）。
