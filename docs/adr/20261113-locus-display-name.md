# シリーズと事物を分け、事物は表示用の地名を持つ（20260902-series-and-loci を supersede）

- **状態**: 採用
- **決定日**: 2026-11-13（#327）
- **関係する ADR**: 20260902-series-and-loci（これを supersede する）、20260829-era-open-end（終わっていない era を表す値）、20260901-map-feature-carries-key-only（地図から返る feature は鍵の運搬に限る）、20260902-two-phase-location（位置情報の段階分け）、20260902-local-only-admin（管理画面は手元でだけ動かす）、20260911-drop-series-kind（`kind` の廃止）、20260911-series-vocabulary-without-kind（手で書く欄の語彙）、20261112-quote-titles-only-without-summary（シリーズは独自の説明の欄を持たない）

## 文脈

20260902-series-and-loci は、事物の `properties` を `id`・`seriesId`・`timeRange` の 3 欄に限った。
事物の `id` は代表点の時代の地名を英語で書いた鍵（例 `pella`・`pengcheng`）で、画面に出す語として書かれていない。
そのため詳細カードは、選んだシリーズの代表点がどこかを文字で示せず、アレクサンドロスを選んでも代表点がペラであることは地図の点の位置からしか読めない。

`region` はシリーズが扱う地理の広がりで、代表点の在る区画とは独立に決まる（20260911-series-vocabulary-without-kind）。
ニコラ・テスラ（代表点はニューヨーク、`region` は `ヨーロッパ`）や鑑真（代表点は奈良、`region` は `中国`）のように、`region` は代表点の位置の代わりにならない。

20261112-quote-titles-only-without-summary は、詳細カードがシリーズについて独自に出すものを年代や場所などの構造化した値に限った。
地名は場所の構造化した値に当たる。

20260902-series-and-loci の決定のうち、`kind` は 20260911-drop-series-kind で廃止され、`data/` は `catalog/` へ改名された。
この版は `kind` の廃止と `catalog/` への改名を反映して旧 ADR を複写し、事物の欄に地名を足す。

## 決定

1. **`catalog/series.json` がシリーズの属性を持つ。**
   geometry を持たず、GeoJSON でもない。
   列は `eras.json` と同じ素の配列
2. **`catalog/loci.geojson` が事物（`locus`、複数形 `loci`）を持つ。**
   GeoJSON FeatureCollection で、地図の source の元になる。
   source へ渡す形はビルド時に組み、properties へ解決した `timeRange` を写す。
   geometry は触らない。
   Feature の `properties` は `id`・`seriesId`・`timeRange`・`name` の 4 欄。
   シリーズと事物の 1 対多は、多の側にある `seriesId` が担う。
   第一段階の geometry は Point だけ
3. **シリーズは `anchor` を持ち、値は代表点の事物 id か、位置なしを表す値 `"unlocated"`（コードでは `ANCHOR_UNLOCATED`）のどちらか。**
   `anchor` は紐づけではなく、そのシリーズの事物のうちどれが代表点かを示す値である。
   null を使わない。
   事物の id に `"unlocated"` は使えない
4. **ファイルをまたぐ整合を `references.ts` が見る。**
   `anchor` が指す事物が実在し、その `seriesId` がそのシリーズを指し、geometry が Point であること。
   位置なしのシリーズが事物を 1 件も持たないこと。
   全事物の `seriesId` が実在するシリーズを指すこと
5. **事物は第一段階から `timeRange` を持つ。**
   値は年の閉区間（`series.timeRange` と同じ形）か、シリーズの `timeRange` と同じことを表す値 `"series"`（コードでは `TIME_RANGE_OF_SERIES`）のどちらか。
   代表点の `timeRange` は `"series"` でなければならない。
   代表点はシリーズ全体を代表するので、年を写して二重に持たない。
   年を書いた事物の `timeRange` は、そのシリーズの `timeRange` に収まっていなければならない（`references.ts`）
6. 役割の欄は持たない。
   代表点は `series.anchor` の参照で見分ける
7. **事物は表示用の地名 `name` を必須の欄として持つ。**
   値は、事物の `id` と同じ地点・同じ時代の名を、日本語の文献で通用する表記で書いた空でない文字列である。
   画面は事物の `id` を地名として出さず、`name` を出す。
   表記の細則は skill `series-vocabulary` が持つ

## 理由

シリーズと図形の多重度を 1 対多にするには、図形を別のファイルへ出すしかない。
属性を持つファイルが geometry を持たなければ、第二段階で重い輪郭がどこに置かれても、人間が読む属性の diff は汚れない。
`loci.geojson` が GeoJSON なので、地図へ渡す形は properties へ鍵で取得した値を写すだけで組める。
geometry を組み直す合成は要らない。

位置なしを専用の値で表すのは、「まだ置いていない」と「置かないと決めた」を分けるためである。
欄の欠落や null はどちらとも読める。
20260829-era-open-end と同じ理由で、読んだ人が意味を推測せずに済む語を置く。

事物に `timeRange` を第一段階から持たせるのは、描画の濃淡が読む欄を段階で変えないためである。
第二段階で欄が増えると、地図へ渡す形も era スライダーの入力も組み直すことになる。
代表点は常にシリーズ全体を代表するので、年を写すと同じ値を二箇所に持つ。
一致を `"series"` の値で表せば、シリーズの `timeRange` を直したときに代表点が追随し忘れることが無い。

地名を事物の欄に持つのは、地名が地点の属性で、地点と同じ行にあれば事物を足す人が同じ場で書き、同じ PR で確かめられるからである。
必須にするのは、欄の欠落を許すと、事物を足した PR が地名を書き忘れても検査が緑のままになるからである。

採らなかった案:

- **代表点の座標を `series.json` へ直に持ち、`loci.geojson` は第二段階で足す** — 第一段階は 1 ファイルで済む。
  ただし第二段階で geometry の置き場が 2 つになり、地図の source も 2 本になる。
  代表点も事物の一つだと最初から置くほうが、形が段階で変わらない
- **`geometry: null`（#95）** — GeoJSON の仕様は許す。
  ただし 1 Feature = 1 geometry のまま 1 対多にできず、null が「未決」か「位置なし」かを語らない
- **事物に `role: "anchor"` の欄を持たせ、シリーズ側は参照を持たない** — 参照の向きが多から一の一方向で済む。
  ただし位置なしは事物の欄では表せず、シリーズ側に「位置なし」の欄が別に要る。
  そのうえで「位置ありなら代表点がちょうど 1 件、位置なしなら 0 件」の検査が要り、二つのファイルにまたがる整合は消えない。
  `anchor` なら「どの事物が代表点か」と「位置なし」が同じ欄に乗り、シリーズの位置に関する宣言が一箇所で読める
- **シリーズ側に事物 id の配列を持たせる** — 事物が増えると `series.json` が再び重くなる。
  参照は多の側から一の側へ向ける
- **代表点に年を写す** — 欄が一つの形で済む。
  ただしシリーズと同じ値を二箇所に持ち、片方だけ直したデータが作れる
- **`timeRange` を第二段階で足す** — 第一段階のスキーマが小さい。
  ただし欄が増えた時点で描画の入力が変わり、第一段階の表示を書き直すことになる
- **DB へ移す** — 20260902-local-only-admin
- **地名を事物の `id` からの変換表として `web/src` に持つ** — `catalog/` の形が変わらない。
  ただし事物を足すたびに `catalog/` とコードの両方を直すことになり、`catalog/` を書く管理画面からは地名を書けない
- **地名を持たず、詳細カードには `region` だけを出す** — 書く値が無い。
  ただし代表点の地点は文字で出ず、`region` が代表点の区画と違うシリーズでは点の位置と食い違う区画だけが出る
- **`name` を任意の欄にし、無ければ画面に出さない** — 事物を足す人の手間が減る。
  ただし書き忘れを検査が捕まえず、地名の出るシリーズと出ないシリーズが黙って混ざる

## 帰結

- 20260901-map-feature-carries-key-only の「読んでよいのは鍵だけ」は変わらない。
  詳細カードは `name` を地図から返る feature でなく、検査に通した事物の集合から `id` で取得する
- 地図へ渡す形は `name` を写さない。
  `catalog/` の形だけが変わる
- 既存の事物すべてに `name` を書く作業と、表記の細則を skill `series-vocabulary` に足す作業が要る。
  値は代表点の典拠（`docs/sources/<シリーズ id>.md`）と照らして人間が確かめる
- 事物を足す PR は、`id` と同時に `name` を書く

## 覆る条件

第二段階に着手して、代表点を事物でなくシリーズの属性として持つほうが扱いやすいと分かったとき。
1 シリーズの事物が多くなり、`loci.geojson` 1 枚で人間が読めなくなったとき（そのときは分割の形を決める）。
地名を画面のどこにも出さなくなったとき（そのときは `name` を消す）。
地名を多言語で出すことになったとき（そのときは欄の形を決め直す）。
