# 0001. スタックを Next.js App Router + TypeScript の static export にする

- **状態**: 採用
- **決定日**: 2026-07-14
- **関係する ADR**: 0007（配信先）

## 文脈

コテンラジオのシリーズを世界地図×時系列に載せる Web アプリを、
転職ポートフォリオ（coten-career と接続）として公開する。
表示するデータはビルド時に確定し、実行時にサーバ側の処理を要さない。

## 決定

Next.js (App Router) + TypeScript を採り、**static export**（`output: 'export'`）で吐く。

## 理由

転職ポートフォリオとして Next.js 習熟を示す（coten-career と接続）。サーバ処理は不要なので実質静的サイト。

採らなかった案:

> **採らなかった案は移設時（2026-08-25）の補足。** 前身の決定表は決定と理由の2列しか持たず、
> 代替案の比較を記録していない。ここでの記述は当時の決定文そのものではなく、
> `docs/adr/README.md` の節構成を満たすための再構成である。


- **サーバを持つ Next.js（SSR / Route Handlers）** — 実行時にサーバ側の処理が要る要件が出たら採る。
  現時点でその要件が無く、配信先の選択肢（0007）を狭める
- **ビルドツールだけの構成（Vite + React 等）** — Next.js 習熟を示すという目的が満たせない

## 帰結

- 実行時 fetch を持たない。RSS の取得は常にビルド前のデータ更新として行う（0005・`ARCHITECTURE.md`）
- 静的ホスティングへ載る（0007）
- static export はビルド時にしか壊れない失敗を持つので、判定の口が `next build` を含む必要がある（0009）

## 覆る条件

実行時にサーバ側の処理が要る機能（ユーザ登録・投稿・検索 API など）を要件に入れると決めたとき。
