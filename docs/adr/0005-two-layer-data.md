# 0005. データを「エピソード = RSS 自動 / テーマ = 人間キュレーション」の二層に分ける

- **状態**: supersede 済み（→ 0029）
- **決定日**: 2026-07-14
- **関係する ADR**: 0029（この決定を supersede する）、0006（配信リンク）

## 文脈

エピソードは今後も増え続ける。一方でテーマの座標・年代・ジオメトリは
番組のメタデータから機械的に導けない。

## 決定

`data/episodes.json` を RSS 由来の自動層、`data/themes.geojson` を人間キュレーションの手動層とし、
エピソードとテーマは `themeId` で結ぶ。エピソード取得は RSS を正とする自動同期（ビルド時スクリプト）で行う。

## 理由

**データ管理の二層分離**: 座標・年代・ジオメトリは自動化できない。自動層と手動層を混ぜると更新のたびに壊れる。

**エピソード取得を RSS 自動同期にする**: 今後の追加に耐える。

採らなかった案:

> **採らなかった案は移設時（2026-08-25）の補足。** 前身の決定表は決定と理由の2列しか持たず、
> 代替案の比較を記録していない。ここでの記述は当時の決定文そのものではなく、
> `docs/adr/README.md` の節構成を満たすための再構成である。


- **全部を手で持つ** — シリーズ 66・エピソード 573 件（2026-08-23 時点）を手で追随できない
- **全部を自動で導く** — テーマの座標と年代が導けない

## 帰結

- `episodes.json` は手で編集しない。編集は同期スクリプトの側を直す
- どのテーマにも割り当たらないエピソードは `data/inbox/` へスタブとして排出し、人間 + Claude の補正対象にする
- 割当は `themes.geojson` の `match` 正規表現が持つので、`match` はスキーマ確定（S2）の後にしか書けない

## 覆る条件

テーマの座標・年代を機械的に導く手段が現れたとき。
