# 0032. 器自身の文書は `docs/` に置き、ルートには道具が要求するものと玄関だけを残す

- **状態**: 採用
- **決定日**: 2026-09-06（#130）
- **関係する ADR**: 0020・0030・0031

## 文脈

ルート直下に md が 6 本あり、器の玄関としては混んでいる。
`docs/adr/` が既にあって文書の家は決まっているのに、上位の 4 文書だけがルートに残っていた。

寄せる先を決めるだけでは足りない。
条件を書かずに寄せると、次に文書が増えたときに同じ問いがもう一度起きる。
#41（`VISION.md` を起こす）が最初の適用先になる。

`ed36ec6` の時点で、参照は次のように散っていた。

- `README.md` が 5 本のリンクで 3 文書を指している
- 上位 3 文書が `docs/adr/` へ 47 本のリンクを持っている
- ADR の本文が 63 箇所でこれらを名指ししている。すべて素の名前で、マークダウンリンクは 1 本も無い
- `web/src/` と `web/scripts/` のコメントが 8 箇所で名指ししている
- 道具は 1 つも依存していない。`.github/workflows/`・`.claude/settings.json`・`.claude/hooks/`・`mise.toml`・`.worktreeinclude` のどれもパスを持たない

## 決定

**ルートに置くのは、道具がその位置を要求するものと、リポジトリの玄関だけである。**
器自身の文書はその条件を満たさないので `docs/` へ置く。

1. `ARCHITECTURE.md`・`HARNESS.md`・`ROADMAP.md` を `docs/` へ移す
2. `README.md`・`CLAUDE.md`・`CODING.md` はルートに残す。
   GitHub が `README.md` を、Claude Code が `CLAUDE.md` をルートで読む。
   `CODING.md` は共有の雛形からの写しなので、位置を動かすと次の追随が取りこぼすかルートへ作り直す
3. `docs/` の中は割らない。
   移した 3 本を `docs/adr/` と並べる
4. **リンクは書いたファイルからの相対、散文のパスはリポジトリのルート起点**とする

置き場の名前（`catalog/` は 0030、`web/src/lib/` の割り方は 0031）と、文書の層そのもの（`CLAUDE.md`「文書の層」）は動かさない。
変えたのは位置だけである。

## 理由

**ルートは読む場所ではなく、道具が最初に見る場所である。**
`README.md` と `CLAUDE.md` がそこに要るのは中身が上位だからではなく、GitHub と Claude Code がそのパスを決め打ちで読むからである。
この条件で測ると、器自身の文書がルートに居る理由は「昔からそこにあった」以外に無い。

**`CODING.md` を残すのは中身ではなく配布の都合による。**
雛形からの写しは、雛形の側を直して配り直すことで追随する（`CLAUDE.md`「配布物の追随」）。
配り先のパスを器の都合で動かすと、次の追随がルートへ元のファイルを作り直し、`docs/` の写しと二つ並ぶ。
`CODING.md` だけルートに残るのは一貫性の破れに見えるが、破れているのは条件ではなく写しの側の制約である。

**リンクと散文でパスの起点を変えるのは、壊れ方が違うからである。**
マークダウンのリンクはファイルからの相対でしか解決しないので、相対で書くほかない。
散文のパスは解決されず読み手が読むだけなので、ルート起点の方がどこから読んでも同じ場所を指す。
`web/src/` のコメントが既に `docs/adr/0004-openfreemap-positron.md` と書いており、散文側はその表記に揃う。

**`docs/` の中を割らない。**
移した 3 本は層が違う（現況・検証・順序）が、層は `CLAUDE.md`「文書の層」が持っており、ディレクトリで表現し直すと同じ知識が二箇所に載る。
`adr/` だけが割れているのは、そこが 1決定1レコードで無限に増える唯一の層だからである。

### 採らなかった案

- **6 本すべてをルートに残す。**
  移動に伴う追随がゼロで、ADR の 63 箇所も陳腐化しない。
  しかしルートを開いた人が、道具が読むファイルと器自身の文書を見分ける手を持たない。
  次に文書が増えるたびに同じ判断が要る
- **`CODING.md` も `docs/` へ移す。**
  「ルートは道具が要求するものだけ」という条件がきれいに揃う。
  しかし雛形の配り先が動くので、次の追随でルートへ作り直されて二つ並ぶ。
  移すなら雛形の側を先に直す必要があり、この器の一存では決められない
- **`docs/` の中を層で割る（`docs/design/`・`docs/process/` など）。**
  層は `CLAUDE.md`「文書の層」が既に持っているので、ディレクトリで書き直すと正が二つになる。
  3 本しか無いものを割る名前は、`schema/` の部品に名前が付かなかったのと同じ理由で決まらない（[0031](0031-lib-layout-by-concern.md)）
- **ADR の本文を書き換えて `docs/` を足す。**
  規約 4 が本文の書き換えを禁じている。
  0020（テーマ→シリーズ）と 0030（`data/`→`catalog/`）で二度使った読み替え注記の形をここでも採る

## 帰結

- ルート直下の md は 3 本になる。
  README は玄関、CLAUDE はセッションの入口、CODING は雛形の写しで、どれも位置が中身以外の理由で決まっている
- ADR の本文にある 63 箇所が、ルート直下を指したまま残る。
  `docs/adr/README.md` へ置いた一行がその橋になり、読み替え規則は 0020・0030 と合わせて三本になる
- #41 が起こす `VISION.md` は `docs/` へ入る。
  条件の適用であって決定ではないので、そのとき ADR は要らない
- `docs/` の中の相互参照は素の名前で足りるようになった。
  3 本は互いに兄弟なので、`ROADMAP.md` と書けば解決する
- CI と配信に影響は無い。
  道具がパスを持たないので、`.github/workflows/` も `mise.toml` も触っていない

## 覆る条件

`docs/` が読み切れない量になったとき。
層で割る名前が決まらないうちは割らないが、量が増えれば `adr/` と同じく「無限に増える層」が他にも現れる。

雛形が `CODING.md` の配り先を変えたとき。
ルートに残す理由が配布の都合だけなので、その都合が消えれば `docs/` へ移せる。
