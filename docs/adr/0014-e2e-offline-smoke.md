# 0014. E2E を入れる（外部を遮断したスモーク1枚に限る）

- **状態**: 採用
- **決定日**: 2026-08-28
- **関係する ADR**: 0009、0013、0003、0004

## 文脈

PR #60 で、maplibre の worker がバンドルされず 404 になり、地図が描画されないまま `pnpm check` が緑で通った。
気付いたのは人間が実機で開いたときで、機械はどの層でも捕まえられなかった。
L2 は jsdom に WebGL が無いので地図の絵を見られず、L3 はビルドの成否しか見ない。

この事故そのものは 0013 の `web/tests/map-worker-assets.test.ts` が塞いでいる。
`public/` から worker の依存を1つ抜くと赤になることを確認した。

残っているのは同じ事故ではなく、同じ**類**の穴である。
配信物が自足していないことに、機械がどこでも気付けない。
0013 が塞いだのはファイルが `public/` に置かれたことまでで、そのファイルへ実際に到達できるかは見ていない。
S8 で GitHub Pages へ載ると `basePath` が経路に効き始めるので、この類が効いてくるのはこれからになる。

`HARNESS.md`「6. 意図的にやらないこと」は「E2E（Playwright）を MVP に入れない。ブラウザを立てる層は要件が出てから足す」と決めていた。
その要件が出たと読む。

## 決定

E2E を入れる。
道具は Playwright、ブラウザは Chromium 1つに限る。

守らせるのは**静的成果物が自足していること**の一点だけである。
`next build` が吐いた `out/` を `BASE_PATH` 込みで配信し、ヘッドレスの Chromium で開いて次の三点を見る。

- 同一オリジンへのリクエストに 4xx / 5xx が無い
- `console.error` が出ない
- 地図の canvas が viewport 大で立つ

外部（タイル・グリフ・スプライト）への通信は遮断し、スタイルだけを合成のフィクスチャで返す。

口は `pnpm check` の中に置く（0009）。
走る位置は `next build` の後で、判定の対象がその出力になる。

**地図の絵が正しいかは見ない。** それは L5（人間の目視）に残す。

配線そのものは #66 が持つ。

## 理由

ヘッドレスのブラウザは地図を描ける。
Playwright の Chromium は WebGL を SwiftShader（ソフトウェアラスタライザ）で通し、`visibilityState` は `visible` になるので、`requestAnimationFrame` が回ってラベルまで描画される。
Claude Code のブラウザペインが `visibilityState: hidden` のまま描画を進めないのは、あの環境の性質であってヘッドレス一般の性質ではない。
**L2 と L3 が原理的に見られないものを、この層は見られる。**

外部を遮断してもこの類の穴は捕まる。
遮断すると背景1色になるので画素の比較は健全な成果物と壊れた成果物を区別できないが、maplibre はスタイルにソースが無くても worker を要求するため、404 の側が残る。
実測は次のとおり（`out/` から worker を消したものを壊れた成果物とした）。

| | 実タイルあり | 外部を遮断 |
|---|---|---|
| 健全な `out/` | 画素サンプル 253 種 / 4xx なし | 6 種 / 4xx なし |
| worker を消した `out/` | 11 種 / worker が 404 | 6 種 / worker が 404 |

事故を捕まえるのは 4xx であって画素ではない。
だから `HARNESS.md`「実 API を自動テストで叩かない」を書き換えずに済み、外部の可用性で CI が赤くなる余地も入らない。

**canvas はこの類の穴を捕まえない。** worker を消した壊れた状態でも `canvas.maplibregl-canvas` は立ち、viewport と同じ寸法を持っていた。
存在も寸法も、健全な成果物と区別が付かない。
それでも寸法を判定へ入れるのは、CSS で高さが 0 になる別の失敗に効かせるためである。
配信物の自足を見るのは 4xx の側だけになる。

### 採らなかった案

- **実タイルまで叩いて画素を見る。** #60 の類に加えてタイル URL やスタイル URL の取り違えも捕まるが、`HARNESS.md`「実 API を自動テストで叩かない」を書き換えることになり、外部の可用性で CI が赤くなる余地が入る。採る条件は、タイル URL の取り違えが実際に事故として出たとき
- **タイルをフィクスチャで再現して画素を見る。** 外部依存を持たずに絵まで守れるが、スタイル 25KB に加えて TileJSON・ベクタタイル・ラスタタイル・グリフ・スプライトが要り、フィクスチャが数 MB になって maplibre の版と一緒に腐る。守れる範囲の増分に対して重い
- **別の口（`pnpm e2e`）にして CI の別 job で必須にする。** 手元の心拍を 10.7 秒のまま保てるが、「これが緑なら閉じてよい」と言える口が二本になり、0009 が畳んだ形へ戻る
- **手元だけで回し CI へ載せない。** CI 時間も egress も増えないが、回し忘れが起きるので機械判定として効かない。実質は L5 の補助にしかならない
- **入れない。** #60 は 0013 が塞いだので要件はまだ出ていない、という読みは成り立つ。採らないのは、塞いだのがファイルの配置であって配信物の自足ではないため。`basePath` の取り違えは同じ緑をすり抜ける

## 帰結

- 手元の `pnpm check` は 10.7 秒から 15 秒前後になる（遮断版のスモーク1本が 3.9 秒）
- CI は Chromium 356MB のダウンロードを持つ。`~/.cache/ms-playwright` をキャッシュしないと毎 run で払う
- リモート（Claude Code on the web）は Playwright の配信元への egress が要る。`HARNESS.md`「4. コンテナの外向き通信」が引き受ける非対称が1件増える
- 配信は `BASE_PATH` 込みで行う。`BASE_PATH` は手元でも効いているので、`/` 直下へ配信すると本番と違う経路を見ることになる
- スモークが緑でも、地図が正しく描かれている保証にはならない。絵の判定は L5 のまま残る
- 検証の層が1つ増えるので、`HARNESS.md` の「人間の目視」は L4 から L5 へ繰り下がる

## 覆る条件

タイル URL やスタイルの取り違えが実際に事故として出たとき。
そのときは実タイルを叩くか、タイルのフィクスチャを持つかを選び直す。

ヘッドレスの WebGL が不安定になり、スモークが偽陽性で赤くなり始めたとき。
判定から canvas の寸法を落とすか、層ごと畳むかを選び直す。
