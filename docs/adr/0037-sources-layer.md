# 0037. `catalog/` の値の典拠を `docs/sources/<シリーズ id>.md` に置く

- **状態**: 採用
- **決定日**: 2026-09-10（#152）
- **関係する ADR**: 0008（引用は題号に限る）、0028（データを編集する管理画面は手元でだけ動かす）、0030（データの置き場の名前を `catalog/` にする）、0032（リポジトリ自身の文書は `docs/` に置く）、0034（手で書く欄の語彙）、0035（歴史の裏どりを `@historian` の別レーンに分ける）

## 文脈

`catalog/series.json` の `timeRange` と `catalog/loci.geojson` の座標は、番組の内容から人手で決める値である。
[0035](0035-history-review-lane.md) が `@historian` のレーンを分け、典拠の URL を添えた指摘が返るようにした。

S7 古代の 6 シリーズ（#101）でそのレーンが 2 回走り、結果は [#143](https://github.com/ta-tabox/coten-atlas/pull/143) の PR コメントと PR 本文の中にだけ在る。
座標の典拠は 1 回目と 2 回目で差し替わっており、2 回目だけが正である。
PR は主題ごとに散り、`series.json` の `id` から辿る道が無い。
半年後に「なぜ `gilgamesh` は `-2800..-2600` か」を問われると、どの PR のどのコメントかを先に探すことになる。

`series.json` は最終的に 66 件を持ち、#102 から #106 までの 50 件も同じ形で溜まる。

## 決定

**`catalog/` の値を決めた根拠を `docs/sources/` に置く。**

| 論点 | 決定 |
|---|---|
| 置き場 | `docs/sources/` |
| 粒度 | 1 シリーズ 1 ファイル |
| 鍵 | ファイル名を `<シリーズ id>.md` にする。連番を振らない |
| ファイルが在ること | そのシリーズの裏どりが済んだ印。争点が無ければ「無し」と書く |
| ファイルが無いこと | 未調査 |
| 中身 | `timeRange` の各欄・代表点の座標・代表点を選んだ判断と候補・仮決定と論点・裏どりの出所。各項に典拠の URL を添える |
| 未決の扱い | 未決を残さない。`catalog/` の値は学説が並立していても 1 つに決め、他の説は「仮決定と論点」節が覆りうる根拠として持つ |
| 公開サイト | 出さない |

### 語の呼び分け

| 語 | 何を指すか | 持つ文書 |
|---|---|---|
| 出典 | 番組の題号と配信リンクを引用したときの帰属 | [0008](0008-quote-titles-only.md)。表記の全文は `/about` |
| 典拠 | `catalog/` の値の史実の裏づけ | `docs/sources/` |

### 典拠の格

座標の典拠には格を添える。
区分は `@historian` の報告の書式（`.github/historian-prompt.md`）が定める一次・二次・三次・参考程度の 4 つに、典拠に使わないものを足した 5 つである。

| 格 | 何を指すか | 値の確からしさを何が担保するか | 例 |
|---|---|---|---|
| 一次 | 対象と同時代に書かれた史料 | 当事者か同時代の記録者が書いたこと。書き手の立場による偏りは残る | カエサル『ガリア戦記』 |
| 二次 | 一次史料や発掘報告を読んで書かれた研究と、専門家が編集する学術的な地名辞典 | 著者と編集者の専門性と、一次史料への参照 | Pleiades |
| 三次 | 研究をまとめた事典・百科と、編集は誰でも行えるが地名辞典の値を取り込んだデータベース | 編集の責任者が辿れること | Britannica・World History Encyclopedia・Wikidata の `P625` |
| 参考程度 | 一次から三次のどれにも当たらない情報源 | 無し。値を決める根拠にせず、並立する説の在り処を示すのに留める | GlobalSecurity.org |
| 典拠に使わない | 内容を自動生成・転載した集約サイト | 無し | `latitude.to`・`geodatos.net` |

## 理由

- **`docs/adr/` に入れない** — 同ディレクトリの規約5 が「決定と読めない事柄は ADR にしない」と定めている。66 件のデータ判断を混ぜると、設計のレコードがその中に埋もれる
- **鍵を `id` にする** — 連番だと `series.json` から引くのに対応表が要る。`id` なら値を疑った人がファイル名を自分で組み立てられる
- **ファイルが在ることを調査済みの印にする** — 争点があるものだけ作ると、「争点なし」と「未調査」が同じ外形になる
- **公開サイトへ出さない** — 出すなら機械が読める形が要り、S5（シリーズ詳細）か S8（仕上げ）の作業になる。読む相手は `catalog/` の値を疑う人に限られる
- **語を呼び分ける** — 「出典」は 0008 が番組の引用の帰属に当てて `/about` に全文を置いている。同じ語で史実の裏づけを指すと、`/about` が持つべき事柄が増えたように読める

採らなかった案:

- **PR のコメントのまま置く** — 層が増えない。ただし PR は主題ごとに散り、`id` から辿る道が無い。座標の典拠のように後から差し替わったとき、どちらが正かがコメントの前後関係にしか無い
- **`series.json` に典拠の欄を足す** — 値と根拠が同じ行に並ぶ。ただし配信するデータの量が典拠の URL の分だけ増え、公開サイトへ出さない決定と整合しない。スキーマも欄ごとに URL の配列を持つ形へ広がる
- **1 ファイルにまとめる（`docs/sources.md`）** — ファイル数が増えない。ただし 66 件が 1 ファイルへ入ると、1 件を足す差分が毎回同じファイルを触り、並行して走る #102 から #106 が必ず conflict する
- **`catalog/` の隣に置く** — データと根拠が近い。ただし `catalog/` はアプリが読む層なので（`ARCHITECTURE.md` §6）、アプリが読まないファイルが混ざる

## 帰結

- S7 古代の 6 シリーズ（`shin-no-shikotei`・`julius-caesar`・`hannibal`・`roshi-soshi`・`kou-to-ryuho`・`gilgamesh`）のファイルを作った。`series.json` の残り 10 件は未調査で、#102 から #106 の 50 件は載せる回に足す
- `docs/sources/README.md` が、ファイルの型と「典拠」の語の範囲を持つ。裏どりの出所は、調査が増えるたびに README が伸びないよう各ファイルが持つ
- `docs/ARCHITECTURE.md` §6 のディレクトリ構造に `docs/sources/` を足す
- **`catalog/` の値を動かしたら、対応するファイルも動かす。** `pnpm check` はこの対応を見ないので、外れても赤くならない
- **`@historian` の報告先は PR コメントのままである。** 0035 が `permissions: contents: read` を決めているので、ワークフローがこのファイルを書くことはない。写すのは人間かセッションである

## 覆る条件

典拠を公開サイトへ出すと決めたとき（機械が読める形が要るので、置き場ごと変わる）。
データを編集する管理画面（[0028](0028-local-only-admin.md)）が典拠の欄も持つようになったとき。
