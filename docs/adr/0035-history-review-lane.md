# 0035. 歴史の裏どりを `@historian` の別レーンに分け、Web 検索を許す

- **状態**: 採用
- **決定日**: 2026-09-09
- **関係する ADR**: 0008（引用は題号に限る）、0010（gh-review の起動を絞るのは job 側の `if:` の一本にする）、0026（位置情報の段階分け）、0034（手で書く欄の語彙）

## 文脈

`catalog/series.json` の `timeRange` と `catalog/loci.geojson` の座標は、番組の内容から人手で決める値である。
`pnpm check` が見るのはスキーマと参照の整合だけなので、生没年が 50 年ずれていても座標が別の大陸を指していても検査は緑になる。

`ROADMAP.md` の閾値 1 は「代表点の位置と年代の精度は叩き台品質で可」と書いており、精度そのものは完了条件でない。
それでも公開するポートフォリオなので、明らかな誤りが載ったままにはできない。
S7 の 6 つの issue は妥当性の判定を「人間の判定（別トラック）」へ置いており、#101（S7 古代の 6 シリーズ）だけで 4 件が積み上がった。
残る #102 から #106 までで 50 件が来る。

既存のワークフロー 2 本はコードのレビューを担う。
`claude-code-review.yml` は `/code-review` を回し、`claude.yml` は `@claude` で同じ観点を実行し直す。
どちらも歴史上の事実を見ない。

## 決定

**歴史上の事実の裏どりを、三本目のワークフロー `.github/workflows/claude-history-review.yml` に分ける。**

1. **起動語は `@historian`。**
   `@claude` を部分文字列として含まない語にする
2. **`WebSearch` と `WebFetch` を許す。**
   典拠の URL を各指摘に付けさせる
3. **ランタイムを入れない。**
   mise・pnpm・Playwright のインストールを持たず、checkout だけで走る
4. **`permissions: contents: read`。**
   起動の絞りと `timeout-minutes`・`concurrency` は既存 2 本と同じ形にする
5. **見るのは `catalog/` の値だけ。**
   `timeRange`・代表点の座標・`region`・`kind`・`title` の 5 つで、コードの品質と設計は見ない

## 理由

裏どりに Web 検索を許すのは、許さないと裏どりが成立しないからである。
年代・地名・人物の同定は言語モデルが自信を持って誤る領域なので、外部の典拠を参照しない第二の意見は、一次と同じ種類の誤りを返す。
しかも二重に確認した外形が付くぶん、確認しない場合より人間の判断を誤らせる。

Web 検索は取得したページの文がプロンプトへ混ざる経路を開く。
このリポジトリは public なので、この経路は塞げない。
ただし `permissions` が `contents: read` でコメントしか残せず、起動も `author_association` で招いた人だけに絞ってあるので、誤った指摘コメント 1 本より先へは届かない。

ランタイムを入れないのは、入れても使い道が無いからである。
歴史の誤りは `pnpm check` では赤くならず、`contents: read` なので直すこともできない。
Playwright のブラウザだけで 356MB あり、毎回のインストールがそのまま無駄になる。

採らなかった案:

- **`claude.yml` の system prompt へ歴史の観点を足す** — ワークフローが 2 本のままで済む。
  ただしコードのレビューを実行するたびに歴史の裏どりも走り、逆も起きる。
  観点を混ぜると、`@claude` を呼ぶ側がどちらを求めているかを宣言できない
- **起動語を `@claude-history` にする** — 名前が `@claude` と揃い、役割の親子が読める。
  ただし `claude.yml` の `if:` が `contains(github.event.comment.body, '@claude')` なので、1 つのコメントで 2 本が走る。
  起動語を分けるのが目的なのに、分けたことにならない
- **Web 検索を許さない** — 外部の文がプロンプトへ入る経路が無い。
  ただし裏どりがモデルの記憶だけになり、上の理由で確認しないより悪くなる
- **セッションの中のスキルにする** — Actions 分を使わず、書いている最中に直せる。
  ただし人間が任意の時点で実行する入口が無い。
  併設は妨げないので、書きながら使う道具が要ると分かった時点で足す
- **ランタイムを入れて `pnpm check` も回せるようにする** — 雛形（`gh-review.md`「実行環境と CI」）の「レビューする側にビルドもテストも回させる」契約に揃う。
  ただしその契約はコードのレビューを対象にしたもので、歴史の裏どりでは回した結果が指摘の材料にならない

## 帰結

- 雛形（fermentary の `tools/gh-review/`）はワークフローを 2 本しか配らないので、`claude-history-review.yml` は追随の対象外である。
  雛形からの逸脱ではなく、雛形が扱っていない領域のリポジトリ固有の追加に当たる
- **最初の実走はこのレコードを main へ入れた次の PR になる。**
  action は定義が default branch と一致しないと自主的に降り、しかも success で終わるので、このワークフローを足す PR の上では検証できない
- **`@claude` を含む起動語を後から選び直せない。**
  選び直すなら `claude.yml` の `if:` を同時に狭める
- 人間の別トラックは消えない。
  裏どりが返すのは典拠付きの指摘までで、代表点を動かすかどうかの採否は人間が決める
- `docs/HARNESS.md`「レビューを掛け直す」節に三本目の実行のしかたを足す
- 起動が 3 経路のコメントすべてなので、PR だけでなく issue の上でも呼べる。
  #102 から #106 の対象表に対して、載せる前に年代を裏どりさせられる

## 覆る条件

裏どりの指摘の質が、典拠を付けても人間の確認の手間を減らさないと分かったとき。
Web 検索の経路から実害が出たとき（そのときは検索を禁じ、典拠は人間が渡す形にする）。
`catalog/` が埋まりきって裏どりの対象が無くなったとき（S7 の完了後。そのときはワークフローを削除する）。
