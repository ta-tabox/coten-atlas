# 0045. 検証の層の番号は `pnpm check` の連鎖の位置だけを表し、人間の目視は番号を持たない

- **状態**: 採用
- **決定日**: 2026-08-29
- **関係する ADR**: 0014（E2E を入れる。帰結で人間の目視を L5 と呼ぶ）、0009（判定の口を `pnpm check` へ移す）

## 文脈

`HARNESS.md`「検証の層構造」は、機械の層を L0 から番号で並べ、人間の目視にも末尾の番号を与えていた。
0014 が L4 のスモークを挟んだ回に、人間の目視は L4 から L5 へ繰り下がり、`web/src/app/page.test.tsx` と `ROADMAP.md` の参照を直すことになった。
操作を伴う E2E の層を足せば、同じ繰り下げがもう一度起きる。

## 決定

番号は `pnpm check` の連鎖の中の位置を表し、安い順に L0 から振る。
人間の目視は番号を持たず、層構造の表では「人間の目視」の名で末尾に置く。

## 理由

`HARNESS.md`「検証の層構造」に置いていた理由を原文のまま写す。

> **人間の目視は番号を持たない。** 連鎖に居らず、close も妨げないので、番号を与えると連鎖の続きに見える。
> 機械層が増えるたびに末尾がずれて、他の文書からの参照も一緒に腐る。
> issue の完了条件は機械判定（`pnpm check`）と人間の判定に分かれており、後者が待ち行列になると前者まで止まる（`ROADMAP.md`「完了条件は二本に分ける」）。

採らなかった案。

- 人間の目視に末尾の番号を与え続ける ／ 機械層を足すたびに番号がずれ、番号で指した他の文書と ADR の参照が腐る

## 帰結

- 0014 が L5 と呼ぶものは人間の目視である。
  0014 の本文は書き換えず、読み替えは `docs/adr/README.md` が持つ
- 層を足すときは機械の層にだけ番号を振り、人間の目視の名は動かない

## 覆る条件

人間の判定が close を妨げる形へ変わり、`pnpm check` の連鎖の一段として扱うと決めたとき。
