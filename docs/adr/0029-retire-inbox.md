# 0029. `data/inbox/` を持たず、未割当は `episodes.json` の `seriesId` を正にする

- **状態**: 採用
- **決定日**: 2026-09-04
- **関係する ADR**: 0005（データを二層に分ける）、0018（割当キーは season）

## 文脈

`data/inbox/` は、どのシリーズにも当たらなかった回を日付ごとに排出する置き場である（[0005](0005-two-layer-data.md) の帰結）。
シードの 10 シリーズを載せた状態で同期を一度回したところ（2026-09-04）、次の三つが揃った。

- inbox が記録するのは「その日に初めて未割当として現れた」という到着の事実だけで、人間が下す判断を書く欄が無い。
  解決した回もそこから消えない
- inbox の欄（`guid`・`title`・`season`・`link`）は `episodes.json` の部分集合で、実測ではどちらも 681 件で一致する
- S7 の era issue は対象の season を表で列挙しており、その出典は #13（season と名前の対応）のコメントである。
  inbox を読む手順がどこにも無い

`web/scripts/inbox.ts` は自身を「人間が開いて編集しうる唯一の生成物」と書いていた。
自動層でも手動層でもない第三の層になっていた。

## 決定

`data/inbox/` を持たない。

- 未割当の正は `episodes.json` の `seriesId` が持つ
- `pnpm sync` は、その時点の未割当を二区分の内訳として標準出力へ出す
  - **規則で確定** — `season` を持たない回と番外編。`series.json` に何を書いても割当は付かない
  - **シリーズ未作成** — `season` を持つのに `series.json` に無い。distinct な season 数を添える

[0005](0005-two-layer-data.md) の決定（自動層と手動層に分ける）は動かさない。
この ADR が置き換えるのは、0005 の帰結のうち「どのテーマにも割り当たらないエピソードは `data/inbox/` へスタブとして排出し、人間 + Claude の補正対象にする」の一行だけである。
二層に分ける決定そのものは生きていて、ヘッダで死んだと宣言すると嘘になるので、0005 のヘッダには `supersede 済み` を足さない。

## 理由

**同じ状態を二か所が持たない。**
いま何が未割当かは `episodes.json` の `seriesId` が持つ。
inbox が同じ問いに別の答えを出せる形を残すと、食い違ったときにどちらが正かを決める規則が要る。

**追跡するのは導けない情報に限る。**
inbox の中身は `episodes.json` から導ける。
導ける情報をコミットすると、読む必要の無い差分が毎回 diff に乗る。

**進捗は sync の出力の方が新しい。**
inbox は排出した日の断面で固まるが、標準出力は走らせるたびにその時点の数を出す。

採らなかった案:

- **inbox に解決済みの印を足す** — 人間が編集する生成物という性質が残る。
  編集を受ける以上スキーマ検査が要り、`episodes.json` と食い違う経路も残る
- **inbox を追跡しない（`.gitignore` へ入れる）** — ファイルは出続けるので実装も検査も残る。
  得られるのは diff から消えることだけである
- **「シリーズ扱いしない season」の除外リストを手動層へ置く** — 2026-09-04 時点の未割当 681 件は全部が規則から導ける。
  規則で導けない例が現れてから作る

## 帰結

- `data/inbox/`・`web/scripts/inbox.ts`・`web/src/lib/schema/inbox.ts` と両者のテストを持たない
- 未割当の内訳を知る口は `pnpm sync` の標準出力である
- 未割当が何件あっても `pnpm check` は緑になる。
  `references.ts` は `seriesId` が null の回を見ないので、割当の進捗は検査の対象でない
- 「規則で確定」と「シリーズ未作成」を分ける述語は `web/src/lib/feed/assign.ts` が持つ。
  割当の規則と内訳の区分が同じ場所に居る

## 覆る条件

人間が回ごとの判断を書き留める必要が出たとき。
いまは判断の結果が `series.json` の 1 行として現れるので、途中の状態を持つ場所が要らない。
