# 0025. 申し送りの層（`NEXT.md`）を畳む

- **状態**: 採用
- **決定日**: 2026-09-01
- **関係する ADR**: 0017

## 文脈

`NEXT.md` は立ち上げ時からセッションを跨ぐ申し送りの置き場として在り、0017 で追跡から外した。
冒頭は自分で「申し送り専用。**作業単位と状態は GitHub Issues**、順序と規約は `ROADMAP.md`。ここに内容を複製しない（複製した瞬間から腐る）」と宣言している。

2026-09-01 に中身を数えたところ、**387 行 24 ブロックのうち、この層でなければ持てない事実は 8 ブロック**だった。

| 区分 | ブロック数 | 正を持っているのは |
|---|---|---|
| 状態の写し | 11 | GitHub Issues / PR / `fermentary/NEXT.md` |
| 決定・経緯の写し | 3 | `docs/adr/`・closed issue #39〜#42 |
| 現況の写し | 1 | `ARCHITECTURE.md` §8 |
| 完了ログ | 1（244 行＝全体の 63%） | git log / PR / `docs/adr/` |
| どこにも無い | 8 | `NEXT.md` だけ |

**写しは腐っていた。**
同日の実測で次が同時に成立していた。
「2 本の PR が実装を終えたまま open で止まっている」（PR #81 はマージ済みで、実際に open だったのは #83 と、本文が存在すら知らない #93）。
「#4 は PR の中で、残っているのはマージだけ」（closed）。
「手つかずで残るのは #19 の 1 件」（#19 は PR #93 の中にあり、手つかずは #92・#95・#96・#97 の 4 件）。
「配布物の追随は未達がいま無い」（同日に検査器のコピーが 5 箇所ずれていた）。
開いている issue の一覧そのものが **#92・#95・#96・#97 を 4 件まるごと落としていた**。

規約の側にも宙に浮いた参照が残っていた。
冒頭が「マージの直前にここを追随させる（規約は `ROADMAP.md`「進め方の横断規約」）」と書いているが、`ROADMAP.md` の当該節にその規約は無い。

## 決定

`NEXT.md` を削除し、**申し送りの層を持たない**。

- 状態の正は GitHub Issues、順序と横断規約の正は `ROADMAP.md`、決定の正は `docs/adr/`、現況の正は `ARCHITECTURE.md`。
  この四つの外に層を作らない
- 構造に関わる未決は `ARCHITECTURE.md` §8「持ち越した開いた問い」が引き取る。
  この節は既に在り、`NEXT.md`「issue にしなかった覚え書き」と役が重複していた
- 特定の issue に着手するとき拾う事実は、その issue の本文へ追記する
- 手元固有の事実は `CLAUDE.local.md` へ（0017 が「手元の生態系との接続は一枚へ集める」と決めた原則の延長）
- 現在地の一枚が要るときは、上の四つから毎回取り直す派生ビューを作る。
  写しを手で保守しない

`.gitignore` から `NEXT.md` の行を外す。
`.worktreeinclude` は対象を持たないファイルとして残し、何を書かないかの理由だけを置く。

## 理由

**状態を持たない約束が守られないのは、書き手の怠慢ではなく層の性質である。**
毎セッションの終わりに「書いておこう」が働き、そのとき最も新しく書きやすい事実は状態なので、状態が入る。
入った状態は次のセッションが更新しない限り腐る。
冒頭の宣言文が守れなかったのは、その文が**書く瞬間に読まれる場所に無い**からで、削って `NEXT.md` を残せば同じ力がまた働く。

**追跡外であることが、腐りを検出不能にしていた。**
`git diff` に出ず、PR のレビューも通らず、リモートのセッションからも見えない。
写しが本体からずれても、気付く経路が構造的に無い。
0017 が追跡を外したのはコンフリクトを消すためで、そのとき検出可能性を失う代償までは数えていなかった。

**「現在地」の役は、取り直せる派生ビューが引き取れる。**
`gh` から毎回取り直す一枚は構造的に腐らない。
手で保守する写しがそれと同じ仕事をする理由が無い。

### 採らなかった案

- **中身を削って 30 行に縮める。** 腐った 16 ブロックは誰かが意図して足したのでなく、上の力が積み上げた結果なので、`NEXT.md` を残せば同じ形へ戻る
- **書き込み専用ツールを配って規約どおり書けるようにする。** ツールが解くのは並行追記の競合であって、状態が入り込むことではない。検査は別に要る
- **追跡下へ戻して腐りをレビューで捕まえる。** 0017 が外した理由（並列 worktree のコンフリクト）がそのまま戻る。写しを検出可能にするために写しを維持する形になっていて、順序が逆である

## 帰結

- セッション開始時に読む一歩目が無くなる。
  続きは開いている issue の一覧から拾う（判定の型は skill `parallel-issues` が持つ）
- worktree へ持ち込むファイルが無くなった。
  `.worktreeinclude` は対象を持たず、何を書かないかの理由の置き場として残る
- **手元でしか持てなかった 8 ブロックのうち、残したのは 4 つだけである。**
  検査器のコピーをバイト一致に保つ規律と、配布物の追随をいつやるかは `CLAUDE.md` へ。
  `series.timeRange` と era 空間の重なりは `ARCHITECTURE.md` §8 へ。
  自動レビューの拒否がゼロにならない件は #10 の本文へ。
  残る 4 つ（文書を 7 枚から 1 枚へ畳んだ経緯・デザインを外部ツールで詰める進め方・その進め方が依存していた期間・順序の一時的な組み替え）は捨てた。
  一つ目は closed issue #40 が本文を持ち、残りは書いた時点の状況にしか効かない
- リポジトリを clone しても失われる情報が減った

## 覆る条件

issue にも ADR にも `ARCHITECTURE.md` §8 にも置けない事実が繰り返し発生し、`CLAUDE.local.md` の一枚では捌けなくなったとき。
**規約の文だけでは守られなかったことがこの決定の根拠なので**、そのときは状態を持たせない仕組みを層と一緒に決める。
