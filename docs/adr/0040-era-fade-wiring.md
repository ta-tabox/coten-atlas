# 0040. 地図の点の濃さは、現在窓との重なりから事物ごとに TypeScript で求めた数値を MapLibre の `circle-opacity` へ渡し、窓と重ならない事物は `filter` で除く

- **状態**: 採用
- **決定日**: 2026-09-11（#137）
- **関係する ADR**: 0022（地図の上に載せるもの）、0023（`kind`）、0026（位置の二段階）、0038（現在窓）

## 文脈

[0038](0038-era-space-window.md) は era 空間の位置から表示の濃さまでを `web/src/lib/era/` の純関数に置き、次の 3 点をスライダーを実装する issue に委ねた。

- 求めた濃さを `web/src/lib/map/series-layer.ts` の `circle-opacity` へどう渡すか
- `kind` ごとの濃さとどう掛け合わせ、窓より長いシリーズを薄く描くか
- `presentEnd` をビルド時に確定させるか、ブラウザで読むか

同じ実装で、スライダーの状態の置き場と表示、地図を開いたときのスライダーの位置も決める必要があった。

MapLibre の `circle-opacity` は feature の properties を読む式を受け取れるので、重なり率と smoothstep を MapLibre の式で書き直すこともできる。
MapLibre のクリックとホバーの判定は円の半径と縁の幅だけを見て、不透明度を見ない（maplibre-gl 6.6.0 の `CircleStyleLayer.queryIntersectsFeature`）。

## 決定

**事物ごとの濃さは `web/src/lib/era/window.ts` の関数で求めて `match` 式へ数値で埋め込み、`kind` の濃さと掛ける。濃さが 0 の事物は `filter` で地図から除く。**

| 論点 | 決定 |
|---|---|
| 濃さを求める場所 | TypeScript。`seriesCircleLayerIn(currentWindow, loci)` が事物ごとに `fadeOpacity(overlapRatio(...))` を求める |
| `circle-opacity` | `["*", <kind の濃さの式>, ["match", ["get", "id"], <id>, <濃さ>, …, 0]]`。窓と重なる事物が無ければ `match` の代わりに `0` を置く |
| 窓と重ならない事物 | `filter` の `["in", ["get", "id"], ["literal", <濃さが 0 を超える事物の id の列>]]` で除く |
| 窓より長いシリーズ | 薄くしない。濃さは `kind` の濃さと窓の濃さの積だけで決まる |
| 濃さの遷移 | `circle-opacity-transition` を `{ duration: 0 }` にする |
| `presentEnd` | ビルドした時点の年。`web/src/app/page.tsx` が `presentEndOf(new Date())` を呼んで `MapCanvas` へ渡す |
| スライダーの状態 | `MapCanvas` の `useState`（`eraPosition`）。`page.tsx` との間に client wrapper を足さない |
| スライダーの表示 | 現在窓の年の範囲を、文字とトラックの上の帯で示す。スライダーが指している 1 年は表示しない |
| 初期位置 | id が `ancient`（古代）の区間の中央。`catalog/eras.json` にその id が無ければ描画時に throw する |
| 目盛り | 1 区間を 100 目盛りに割った `<input type="range">`。キーボードの操作はブラウザ既定の挙動に任せる |

## 理由

- **濃さを TypeScript で求める** — 重なり率と smoothstep の計算が `window.ts` の一か所に留まり、その単体テストがそのまま地図の濃さの検証になる
- **濃さが 0 の事物を filter で除く** — 不透明度だけを 0 にすると、何も見えない場所のクリックで詳細カードが開き、ホバーでカーソルが指の形に変わる
- **窓より長いシリーズを薄くしない** — 窓がシリーズの期間の内側にある間、そのシリーズはその時代の話なので、濃く描くのが「どの時代の話か」を示す目的に合う
- **遷移を 0 にする** — MapLibre は feature ごとに値が変わる式を遷移の途中で補間せず、遷移が終わるまで前の値を描き続ける（maplibre-gl 6.6.0 の `DataDrivenProperty.interpolate`）。既定の 300ms を残すと、スライダーを動かしている間は濃さが変わらない
- **`presentEnd` をビルド時に確定させる** — `catalog/` の読み込みも地図へ渡す形の組み立てもビルド時なので、年だけをブラウザで読む理由が無い。`MapCanvas` が時計を読まないので、テストが実行時刻に依存しない
- **状態を `MapCanvas` に置く** — 位置を読む `SeriesLayers` と `EraSlider` はどちらも `MapLibreMap` の子で、wrapper を挟んでも位置は `MapCanvas` を props で通り抜けるだけになる
- **現在窓の年の範囲を表示する** — 地図に描かれるのは窓と重なるシリーズなので、表示が窓の範囲と一致していれば、描かれたシリーズがなぜ描かれているかを表示から読める
- **初期位置を古代の中央にする** — 2026-09-11 時点の `catalog/` で、地図に出る年を持つ 33 シリーズ（年を持ち、事物を持つシリーズ）と重なる数は、7 つの era の区間の中央のうち古代の中央が最も多い（10 シリーズ、初期の現在窓は前463年〜213年）
- **1 区間を 100 目盛りにする** — 窓の幅が 0.5 区間なので、矢印キー 1 回で窓が自身の幅の 50 分の 1 だけ動き、キーボードでも濃さの変化を追える

採らなかった案:

- **重なり率と smoothstep を MapLibre の式で書き、窓の両端の年だけを式へ渡す** — 式の長さが事物の数によらず一定になる。ただし `window.ts` と同じ計算が式にも置かれ、片方だけを直すと単体テストが通ったまま地図の濃さがずれる
- **`feature-state` で事物ごとの濃さを渡す** — 濃さを変えるたびに source のタイルを読み直さずに済む。ただし `setFeatureState` を事物の数だけ呼ぶ命令的な経路になり、レイヤの定義を値として検証できなくなる。source に `promoteId` も要る
- **不透明度だけを 0 にして filter を使わない** — レイヤの変更が 1 欄で閉じる。ただし見えない円がクリックとホバーを受け取る
- **クリックとホバーの処理で濃さが 0 の事物を無視する** — レイヤの `filter` が要らない。ただし `MapCanvas` のイベント処理が濃さの計算結果を知ることになり、描く対象と操作できる対象が別の場所で決まる
- **窓より長いシリーズほど薄くする** — 短いシリーズが目立つ。ただし長いシリーズはスライダーがどこを指しても薄く、地図から消えたように見える
- **ブラウザで `presentEndOf(new Date())` を読む** — 年が変わるとデプロイし直さずに右端が追随する。ただし `MapCanvas` のテストが実行時刻に依存する
- **状態を `page.tsx` 直下の client wrapper に置く** — `MapCanvas` が地図の描画だけを担う。ただし位置を読むのは `MapCanvas` の子だけなので、wrapper は props を中継するだけになる
- **スライダーが指している 1 年を表示する** — 表示が 1 語で済む。ただしその年を含まないシリーズも窓の端に重なれば描かれるので、表示の年と地図が食い違って見える（1860 年を指すと、1859 年に終わる吉田松陰が描かれる）
- **初期位置を era 空間の中央（0.5）にする** — `catalog/eras.json` の区間の割り方によらない。ただし 2026-09-11 時点では近世の中ほどを指し、初期の現在窓（1538年〜1713年）に重なる地図のシリーズは 9 件で、古代の中央の 10 件より少ない

## 帰結

- スライダーを動かすたびに `match` 式と `filter` が変わり、MapLibre は source のタイルを読み直す（`Style.setPaintProperty` と `Style.setFilter` が `_updateLayer` を呼ぶ）。`match` の組と `filter` の id の列は事物の数だけ伸びる
- `presentEnd` はデプロイし直すまで動かない。デプロイが途絶えると、戦後の区間の右端は最後にビルドした年に留まる
- `catalog/eras.json` の区間を割り直して id `ancient` を消すと、`pnpm build` がプリレンダの throw で止まる
- 古代の中央と近世の中ほどで重なる数の差は、2026-09-11 時点で 1 シリーズしかない。S7 でシリーズが増えて最も多く重なる区間が変わったら、`MapCanvas` の `INITIAL_ERA_ID` の値を変える
- 詳細カードで選んだシリーズの点が窓の外へ出ても、カードは閉じない
- `prefers-reduced-motion` で止めるアニメーションは、地図の円にもスライダーにも無い
- フェードの速さと現在窓の幅が操作の感覚に合うかは人間の目視で判定する。合わなければ 0038 の窓の幅へ差し戻す

## 覆る条件

第二段階（[0026](0026-two-phase-location.md)）で事物が増え、スライダーの操作中に地図の描画が遅れるようになったとき（`feature-state` か MapLibre の式で計算する案へ移る）。
MapLibre が feature ごとに値が変わる式の遷移を補間するようになったとき（遷移を 0 にする理由が消える）。
