# 0020. 地図の 1 エントリの呼び名を `series` にする

- **状態**: 採用
- **決定日**: 2026-08-30（#79）
- **関係する ADR**: 0005・0018

## 文脈

地図に載る 1 エントリを、起草時から `theme`・`themes.geojson`・日本語では「テーマ」と呼んできた（0005）。

この語は実態より広い。
読み手は「一つのテーマ（資本主義）に複数のシリーズがありうる」と読めるが、0018 で **1 エントリ = 1 シリーズ = `itunes:season` の 1 値**が確定しており、束ねる余地は無い。

広いまま残っているのは呼び名の側だけである。
`CLAUDE.md` の目的行は「各シリーズ（テーマ）」と書いて、読み手へ読み替えを要求していた。
`ROADMAP.md` の完了判定が数えるのも「シリーズ数」で、`ARCHITECTURE.md` §3 は「1 テーマ = 1 シリーズ」という同一視を明文で持っていた。

`data/themes.geojson` はまだ存在せず（#4 が初めて書く）、`data/episodes.json` と `data/inbox/` も無い（#27）。
いま動かせば、動くのは定義とコードだけで済む。

## 決定

**地図の 1 エントリの呼び名を `series`（日本語では「シリーズ」）にする。**

1. スキーマの名前を揃える。
   `web/src/lib/schema/theme.ts` は `series.ts` になり、4 つのスキーマ・入口の関数・3 つの型が `series` / `Series` を名乗る
2. エピソードが指す先の欄を `themeId` から `seriesId` へ
3. データファイルの名は `series.geojson`。
   現物はまだ無いので、直すのは検査の対応表と `data/LICENSE` の対象一覧
4. 追跡している文書から「テーマ」の語を落とす

**既存 ADR の本文は書き換えない。**
0019 までのレコードは「テーマ」の語で書かれたまま残り、読み替えの案内を `docs/adr/README.md` へ一行置く。

## 理由

**正しい語は最初から `series` の側にある。**
割当キーが `itunes:season` である以上（0018）、1 エントリが指せるのは 1 シリーズだけで、`theme` はその別名として居座っている。
別名のほうを畳めば、読み替えの要求そのものが消える。

**いま変えれば現物が動かない。**
`series.geojson` は #4 が、`episodes.json` の `seriesId` は #27 が初めて書くので、その 2 つが入った後だとキュレーション済みの現物とファイル名まで改名の対象になる。

**既存 ADR を書き換えなかったのは、規約 4（本文を一字も削らない）を守るため。**
0017 が一度だけ例外を適用しているが、あれは公開に先立ち外から解けない語彙を落とす回だった。
二度目に使えば「一度きり」が運用でなくなる。

### 採らなかった案

- **既存 ADR の本文も置き換える。** 全文書で語が一つに揃うが、規約 4 の例外が二度目になる。追記のみという性質は、例外の回数を数えられるうちしか保たない
- **`theme` のまま、意味の側を文書で狭める。** ファイルを一つも動かさずに済むが、`ARCHITECTURE.md` が既にそれをやっており（「1 テーマ = 1 シリーズ」）、読み替えの要求は消えていない
- **#4 と #27 が入ってから改名する。** 実装の順序を乱さないが、そのときには現物とファイル名が改名の対象に加わる

## 帰結

- 0019 までのレコードと、現在のコード・文書とで語彙が割れる。
  `docs/adr/README.md` へ置いた一行がその橋になる
- 下流の issue（#4・#5・#6・#19・#27・#62・#41）の本文も同じ語彙へ揃えた。
  issue は作業の正典なので、古い名前が残ると次に着手した人がそちらで実装する
- `kind` の 4 値（`point` / `polygon` / `line` / `concept`）と `timeRange` の形は動かない。
  改名したのは 1 エントリの呼び名だけである

## 覆る条件

1 エントリが複数の `itunes:season` を束ねるようになったとき。
束ねた単位には「シリーズ」より広い名が要るので、0018 の割当キーごと問い直す。
