# デザイン規約（UI に触るとき）

UI に当てる規則だけを置き、なぜこの見た目かの決定と経緯は `docs/adr/`、画面構成の現況は `docs/ARCHITECTURE.md` が持つ。
雛形は骨格しか持たないので、見出しはリポジトリで使うものだけ残し、各項はリポジトリの初回 UI セッションで決めたことを書く。

  生の値はトークンの定義にだけ現れる

## コンポーネント
- 既存のコンポーネントで表せるものは既存で表す
  新造するなら既存との境界を一行で書く
- 状態（loading / empty / error）を持つ UI は三つを揃えて作る
- CSS とテストが DOM を指すときは `data-*` 属性で指す
  className は見た目の都合で変わる
- 1 ファイル 1 コンポーネント
  同じファイルに二つ目を書きたくなったら、別ファイルへ切る
- コンポーネントが画面のどこに置かれるか（重ねる位置・幅）は親が持ち、子は自分の中身だけを描く
  子の冒頭コメントと props は、置かれる位置に触れない
- className の並びを定数に持たない
  同じ並びを名指したくなったら、それはその要素を部品として切り出す合図
- ユーティリティクラスの並びが一行で読めない長さになったら、CSS へ移す
- （リポジトリのコンポーネントの置き場と命名をここに書く）

## 文言

- 利用者へ出す文は、状況を言う一文と操作を一つにする（「処理に失敗した。」と「再読み込み」）
  説明・言い訳・比喩を足さない
