# デザイン規約（UI に触るとき）

UI に当てる規則だけを置き、なぜこの見た目かの決定と経緯は `docs/adr/`、画面構成の現況は `docs/ARCHITECTURE.md` が持つ。

## トークン
- 色・字体・間隔・角丸は名前付きのトークンを参照する
  生の値はトークンの定義にだけ現れる
- トークンの置き場は `web/src/app/globals.css` の `@theme` で、部品は Tailwind のユーティリティの名前（`bg-paper`・`text-ink-muted`・`font-heading`・`rounded-box`）で参照する
- 足すときは、同じ役割の既存のトークンで表せないことを確かめてから、`@theme` に名前空間（`--color-*`・`--font-*`・`--radius-*`）を付けて 1 行足す
  色の名前は色相でなく役割（地・罫線・文字・見出し・点・選択）で付ける
- 地図の円と輪の色のトークン（`--color-point`・`--color-selected`・`--color-contemporary`）を変えるときは、`web/src/lib/map/layers/shared.ts` の `MAP_COLORS` も同じ値に直す
  一致は `web/tests/map-colors.test.ts` が見る

## レイアウト
- 余白の単位は `--spacing`（0.25rem）で、`p-3`・`gap-1.5` のように単位の倍数で書く
- ブレークポイントは Tailwind の既定（`sm` 40rem・`md` 48rem・`lg` 64rem）を使い、独自の値を足さない

## コンポーネント
- 既存のコンポーネントで表せるものは既存で表す
  新造するなら既存との境界を一行で書く
- 状態（loading / empty / error）を持つ UI は三つを揃えて作る
- CSS とテストが DOM を指すときは `data-*` 属性で指す
  className は見た目の都合で変わる
- 1 ファイル 1 コンポーネント
  同じファイルに二つ目を書きたくなったら、別ファイルへ切る
- コンポーネントが画面のどこに置かれるか（重ねる位置・幅）は親が持ち、子は自分の中身だけを描く
  子の冒頭コメントと props は、置かれる位置に触れない
- className の並びを定数に持たない
  同じ並びを名指したくなったら、それはその要素を部品として切り出す合図
- ユーティリティクラスの並びが一行で読めない長さになったら、CSS へ移す
- 公開画面の部品は `web/src/components/<画面の要素>/` に置き、管理画面の部品は `web/src/components/admin/` に置く
  ファイル名は部品の名前の PascalCase（`SeriesPanelItem.tsx`）にし、テストは隣に `<名前>.test.tsx` で置く

## 文言
- UI の文言は `writing.md` の四規律に従い、記号や英略語でなく文で書く
- 利用者へ出す文は、状況を言う一文と操作を一つにする（「処理に失敗した。」と「再読み込み」）
  説明・言い訳・比喩を足さない
- （用語集があるリポジトリはその置き場を書く）

## アクセシビリティ
- 操作はキーボードだけで完結させ、状態は色に加えて文字か形で伝える
- （リポジトリで採る基準があれば書く）

## プロジェクト固有（育てる欄）
- 地図の上に重ねる部品の背景は不透明にし、半透明の背景と `backdrop-blur` を使わない
  半透明だと、部品が重なった位置で下の文字が透けて読めなくなる
