# シリーズの語彙 — `series.json` へ 1 件書く手順

`catalog/series.json` と `catalog/loci.geojson` へシリーズを 1 件足すときに、人手で書く欄の値を書く順に決める手順である。
`pnpm check`（`web/src/lib/schema/series.ts`）が見るのは 1 件の中で閉じる規則だけなので、読み・地理・主題の知識が要る判定は、検査が緑でもセッションごとに揃わない。

各規則をそう決めた理由は [ADR-0034（手で書く欄の語彙）](../../../docs/adr/0034-series-vocabulary.md) が持つ。
このスキルと ADR-0034 が食い違ったら ADR-0034 に従い、このスキルを直す。

下の 8 手順を上から順に行う。
代表点と `region` の判定は種別を使うので、`tags` を先に決める。
`timeRange`・`season`・`summary`・`links` は語彙の規則を持たないので、この手順は扱わない。
欄の形は `docs/ARCHITECTURE.md` §3（データモデル）が持つ。

## 1. 現物を読む

主題の語は `catalog/series.json` の現物が正なので、書く前に既存の `tags` を数える。
事物の `id` は事物間で一意なので、既存の事物の `id` も並べる。
どちらもリポジトリのルートで実行する。

```bash
jq -r '.[].tags[]' catalog/series.json | sort | uniq -c | sort -rn
jq -r '.features[].properties.id' catalog/loci.geojson
```

時代別の issue は並行して走るので、他のブランチが足した主題と事物の `id` は main へ入るまで見えない。
main を取り込むたびに、この二つを数え直す。

## 2. `title`

`title` は番組のシリーズ名である。
`season` とシリーズ名の対応は #13（`itunes:season` とシリーズ名の対応の実測）のコメントが正である。

| シリーズ名 | `title` |
|---|---|
| コーナー名 `ショート`・`ジンブンガク` で始まる | コーナー名と直後の空白を除く（`ショート 紫式部` → `紫式部`） |
| それ以外 | シリーズ名のまま |

`title` がコーナー名で始まれば検査が赤になる。

## 3. `id`

`id` は `title` の読みをローマ字にした kebab-case である。
事物の `seriesId`・エピソードの `seriesId`・典拠のファイル名がこの値を指すので、後から変えると参照がすべて変わる。

| `title` の部分 | 規則 | 例 |
|---|---|---|
| 漢字とかな | 日本語の読みをヘボン式でローマ字にする（`し`・`ち`・`つ`・`ふ`・`じ` は `shi`・`chi`・`tsu`・`fu`・`ji`） | `yoshida-shoin`・`shokatsu-komei` |
| 長音 | 記号でも母音の重ねでも表さない。`ou`・`oo` は `o`、`uu` は `u` にし、`ei`・`ii` はそのまま書く | `shukyo`（`shūkyō`・`shuukyou` でない）・`komei`・`teisei-roma` |
| 長音に続く同じ母音の字 | 長音と別の字として書く | `kou-to-ryuho`（`項羽` は `こう` と `う`） |
| `ん` | 後ろの音によらず `n` にする | `sandai`・`genpei`（`gempei` でない） |
| 語の区切り | 語と語の境目と、助詞の前後に `-` を入れる。辞書に一語で載る語と、接頭辞・接尾辞の付いた語は割らない | `sekai-sandai-shukyo`・`shin-no-shikotei`（`shi-kotei` でない）・`america-kaitakushi`（`kaitaku-shi` でない）・`okane-no-rekishi` |
| 助詞 | 語として残す。`title` の表記に無くても、読みに在れば書く | `saicho-to-kukai`・`sugawara-no-michizane`（`菅原道真`） |
| カタカナの外来固有名 | カタカナの語形に合うラテン文字の綴りを使う。語形に合う綴りが複数あれば、英語の文献で通用するものを使う | `sparta`（`suparuta` でない）・`hitler`・`alexandros`（`alexander` はアレクサンダーの語形）・`cleopatra`（`kleopatra` でない）・`chinggis-khan`（`genghis-khan` はジンギスの語形） |
| 発音区別符号（`š`・`ü`・`é` など） | 付けず、元の字だけを書く | `gilgamesh`（`gilgameš` でない）・`levi-strauss`（`lévi-strauss` でない） |
| 大文字 | 小文字にする | `hitler`（`Hitler` でない） |
| `・`・`＝`・空白 | `-` に置き換える | `roshi-soshi`・`levi-strauss`・`julius-caesar` |
| `'`・`.` | 除く | `jeanne-darc`（ジャンヌ・ダルク） |
| 序数 | 算用数字にする | `elizabeth-1` |
| コーナー名 | `title` と同じく除く | |

1 つの `title` に漢字とカタカナが混ざるときは、部分ごとに上の規則を当てる（`america-kaitakushi`・`teisei-roma`）。
検査が見るのは重複だけで、読みどおりかは見ない。

## 4. `tags`

`tags` は種別を最低 1 つと主題を 0 個以上持ち、合わせて 4 個以内である。

### 種別

当てはまる種別をすべて入れる。
一覧の正は `web/src/lib/schema/series.ts` の `SERIES_CATEGORY_TAGS` である。

| 値 | 当てるもの | 現物の例 |
|---|---|---|
| `人物` | 一人か数人の生涯を追う | 吉田松陰・項羽と劉邦 |
| `集団` | 国家・帝国・社会層など、続く人の集まり | スパルタ・帝政ローマ |
| `出来事` | 始まりと終わりのある事の運び | アメリカ開拓史 |
| `概念史` | 主題を時代を跨いで追う | お金の歴史・世界三大宗教 |

人物と出来事の両方であるシリーズ（サラディンと十字軍）は `人物` と `出来事` を両方入れる。
種別は `kind` と別の軸なので、老子・荘子は種別が `人物` で `kind` が `concept` である。

手順 5（代表点と `kind`）と手順 6（`region`）は種別を一つに絞って使う。
種別が複数あるシリーズは、`title` の中心になる語が当たる種別に絞る。
中心になる語は、`A の B` なら B、`A と B`・`A・B` なら A、複合語なら最後の語である（`秦の始皇帝` は `始皇帝`、`サラディンと十字軍` は `サラディン`、`ペリー来航` は `来航`）。

### 主題

1. 手順 1（現物を読む）で数えた既存の語から選ぶ
2. 既存のどの語でも言えないときだけ、新しい語を足す。
   既存の語の下位語は既存の語で言えるものとみなす（`戦争` が在るなら `内戦` を足さない）
3. 新しい語は名詞 1 語で書く。
   `史`・`時代` を付けず、複合語にしない（`戦争史` でなく `戦争`、`宗教思想` でなく `宗教` と `思想`）
4. 種別と合わせて 4 個を超えたら、手順 1 の集計で件数が少ない主題から削る。
   種別は削らない

| 入れない | 例 |
|---|---|
| 地域名 | `日本`・`ギリシア` |
| `catalog/eras.json` と同じ粒度の時代名 | `先史`・`古代`・`中世`・`近世`・`近代`・`19世紀`・`20世紀`・`戦後` |
| コーナー名 | `ショート`・`ジンブンガク` |
| 別の区画にも同じ名の時代がある時代名 | `戦国`（中国と日本の両方にある） |

era より細かい固有の時代名で、別の区画に同じ名の時代が無いものは入れてよい（`幕末`・`三国志`）。

検査が見るのは種別の有無・個数・era と同じ粒度の時代名だけで、上の表の残りの行と、既存の語と同じ意味の新語や複合語は見ない。

## 5. 代表点と `kind`

代表点と `kind` は、主題の中心の場所で決める。
中心の場所は、人物なら活動の拠点（治めた国や仕えた国の都を含む）、集団なら本拠の都市、出来事なら主な舞台である。
種別が複数あるシリーズは、手順 4（`tags`）で一つに絞った種別で決める。

次の表を上の行から当て、最初に当てはまった行の値を書く。

| 順 | 状況 | `anchor` | `kind` | 例 |
|---|---|---|---|---|
| 1 | 種別が `概念史` だけ | `"unlocated"` | `concept` | 世界三大宗教・お金の歴史・ショート 切腹 |
| 2 | 出来事の舞台が複数の区画に対等に跨る | `"unlocated"` | `concept` | |
| 3 | 中心の場所が伝わっている | 中心の場所の事物の `id` | `place` | スパルタ → `sparta-city`・吉田松陰 → `hagi`・ハンニバル → `carthage` |
| 4 | 中心の場所が伝わらず、生地が伝わっている | 生地の事物の `id` | `concept` | 老子・荘子 → `ku`（老子の伝承上の生地） |
| 5 | 中心の場所も生地も伝わらない | `"unlocated"` | `concept` | |

`kind: place` と `anchor: "unlocated"` の組は検査が赤にする。
位置なしのシリーズは `loci.geojson` に事物を足さない。
代表点の座標に正確さは求めない。
`loci.geojson` へ足す Feature の形は、`docs/ARCHITECTURE.md` §3 の例と現物に揃える。
`coordinates` は GeoJSON の順なので、経度が先で緯度が後である。
検査は経度を ±180 度・緯度を ±90 度の範囲で見るので、緯度と経度を入れ違えて赤になるのは経度の絶対値が 90 度を超える地点だけである（`hagi` の 131.399 は赤になり、`carthage` の 10.323 は赤にならない）。

事物の `id` は、シリーズの `title` でなく代表点の地名から次の表で作る。

| 対象 | 規則 | 例 |
|---|---|---|
| 地名 | 代表点に選んだ理由になった時代の、その地点の名を使う。現在の名にしない | `pengcheng`（現在の徐州。`xuzhou` でない）・`ku`（苦県。現在の鹿邑。`luyi` でない）・`uruk` |
| 綴り | 英語の文献で通用する表記を使い、日本語の読みにしない。中国の地名は声調記号を付けないピンインで書く | `xianyang`（`kanyo` でない）・`carthage`・`rome`（シリーズ `teisei-roma` の `roma` と別の規則で決まる） |
| 行政区分の語（県・郡・州・市・County など） | 付けない | `ku`（`ku-county`・`kuxian` でない） |
| 発音区別符号・長音・大文字・空白・`'`・`.` | シリーズの `id` の表と同じ規則を当てる | `st-louis`（St. Louis） |
| シリーズの `id` と同じ文字列になる | 地点の種類を表す英語を `-` で後ろに付ける。行政区分の語を付けない規則より先に当てる | `sparta-city`（シリーズ `sparta`） |
| 同じ地名を二つのシリーズが要求する | より具体的な地点名を使う | `forum-romanum`（`rome` をシリーズ `teisei-roma` が使う） |
| 人名・シリーズ名 | 使わない | シリーズ `hannibal` の代表点は `carthage` |

検査が見るのは重複と `unlocated` の使用だけで、代表点の時代の地名を英語で書いたものかどうかは見ない。

## 6. `region`

`region` はそのシリーズが扱う地理の広がりを表し、代表点の在る区画とは独立に決まる。
位置なしのシリーズも区画を持てる。

値は次の 13 個から 1 つ選ぶ。
一覧の正は `web/src/lib/schema/series.ts` の `SERIES_REGIONS` で、値を足すには新しい ADR が要る。

`日本` / `朝鮮半島` / `中国` / `東南アジア` / `南アジア` / `中央ユーラシア` / `西アジア` / `アフリカ` / `ヨーロッパ` / `北アメリカ` / `南アメリカ` / `オセアニア` / `地域なし`

次の表を上の行から当て、最初に当てはまった行の値を書く。

| 順 | 状況 | 値 | 例 |
|---|---|---|---|
| 1 | 扱う地理が一区画に収まる | その区画 | 秦の始皇帝 → `中国`・ショート 切腹（位置なし） → `日本` |
| 2 | 複数の区画に跨るが、下の表の本拠が一つの区画に決まる | 本拠の区画 | アレクサンドロス → `ヨーロッパ`・ハンニバル → `アフリカ` |
| 3 | 複数の区画に跨り、下の表の本拠が無い | `地域なし` | 世界三大宗教 |

本拠は、手順 4（`tags`）で一つに絞った種別で決める。

| 種別 | 本拠 | 本拠が無いとき | 例 |
|---|---|---|---|
| `人物` | 生地。生地が伝わっていなければ活動の中心 | （常に在る） | アレクサンドロス（ペラ）→ `ヨーロッパ`・ハンニバル（カルタゴ）→ `アフリカ` |
| `集団` | 発祥の地 | （常に在る） | 帝政ローマ（ローマ）→ `ヨーロッパ` |
| `出来事` | 主な舞台 | 舞台が複数の区画に対等に跨る | ペリー来航（浦賀）→ `日本` |
| `概念史` | 一つの区画で生まれて他へ広がったなら、生まれた区画 | 複数の区画で別々に生まれた | 世界三大宗教・お金の歴史 → `地域なし` |

`地域なし` を選ぶかどうかは `anchor` が `"unlocated"` かどうかと独立で、本拠が一つの区画に決まるシリーズには使わない。

代表点や本拠が二つの区画に読める位置にあるときは、次の表に従う。

| 継ぎ目 | 区画 |
|---|---|
| ロシア | ウラル山脈以西は `ヨーロッパ`、以東は `中央ユーラシア` |
| 北アフリカ（エジプトを含む） | `アフリカ` |
| アナトリア | `西アジア`（イスタンブールの欧州側も含め、トルコを割らない） |
| モンゴル高原・中央アジア | `中央ユーラシア`（チベットと満洲は `中国`） |
| メキシコ・中米・カリブ | `北アメリカ` |

検査が見るのは 13 値のどれかであることだけで、区画の選び方は見ない。

## 7. 検査と見直し

`web/` で `pnpm check` を回し、緑にする。
緑になった後に、検査で見られない次の判定を見直す。

| 見直すこと | 当て直す手順 |
|---|---|
| `id` が読みどおりか | 手順 3（`id`）の表 |
| `tags` に入れない語が無いか | 手順 4（`tags`）の「入れない」の表 |
| 新しく足した主題が既存の語と同じ意味の語・下位語・複合語でないか | main を取り込み、手順 1（現物を読む）の集計を回し直す |
| 事物の `id` が代表点の時代の地名を英語で書いたものか | 手順 5（代表点と `kind`）の事物の `id` の表 |
| `anchor` と `kind` が主題の中心の場所で決まっているか | 手順 5（代表点と `kind`）の表を上の行から当て直す |
| `coordinates` が経度・緯度の順か | 手順 5（代表点と `kind`） |
| `region` を区画にするか `地域なし` にするか、本拠をどの種別の基準で決めたか | 手順 6（`region`）の二つの表を上の行から当て直す |

## 8. 典拠を記録する

`@historian`（`.github/workflows/claude-history-review.yml`）の裏どりが返り、人間が値を決めた後に、典拠を `docs/sources/<シリーズ id>.md` へ記録する。
ファイルが在ることがそのシリーズの裏どりが済んだ印になるので、裏どりの前にファイルを作らない。
レコードの書式は [ADR-0037（典拠の層）](../../../docs/adr/0037-sources-layer.md) が持ち、節の並びは `docs/sources/README.md` が持つ。
`pnpm check` はファイルと `catalog/` の値の対応を見ないので、記録した後に `catalog/` の値を動かしたら同じファイルも直す。

## 規則が決めていない表記に当たったとき

ADR-0034 が決めていない表記に当たったら、既存の現物に揃え、選んだ表記と根拠を PR 本文に書く。
規則の正は ADR-0034 なので、規則はこのスキルへ先に書き足さず、ADR-0034 に足してからこのスキルを追随させる。
