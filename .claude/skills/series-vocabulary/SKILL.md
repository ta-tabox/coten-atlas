# シリーズの語彙 — `series.json` へ 1 件書く手順

`catalog/series.json` と `catalog/loci.geojson` へシリーズを 1 件足すときに、人手で書く欄の値を書く順に決める手順である。
`pnpm check`（`web/src/lib/schema/series.ts`）が見るのは 1 件の中で閉じる規則だけなので、読み・地理・主題の知識が要る判定は、検査が緑でもセッションごとに揃わない。

各規則をそう決めた理由は [ADR-0034（手で書く欄の語彙）](../../../docs/adr/0034-series-vocabulary.md) が持つ。
このスキルと ADR-0034 が食い違ったら ADR-0034 に従い、このスキルを直す。

下の 8 手順を上から順に行う。
`timeRange`・`season`・`summary`・`links` は語彙の規則を持たないので、この手順は扱わない。
欄の形は `docs/ARCHITECTURE.md` §3（データモデル）が持つ。

## 1. 現物を読む

主題の語は `catalog/series.json` の現物が正なので、書く前に既存の `tags` を数える。
事物の `id` は事物間で一意なので、既存の事物の `id` も並べる。
どちらもリポジトリのルートで実行する。

```bash
jq -r '.[].tags[]' catalog/series.json | sort | uniq -c | sort -rn
jq -r '.features[].properties.id' catalog/loci.geojson
```

時代別の issue は並行して走るので、他のブランチが足した主題と事物の `id` は main へ入るまで見えない。
main を取り込むたびに、この二つを数え直す。

## 2. `title`

`title` は番組のシリーズ名である。
`season` とシリーズ名の対応は #13（`itunes:season` とシリーズ名の対応の実測）のコメントが正である。

| シリーズ名 | `title` |
|---|---|
| コーナー名 `ショート`・`ジンブンガク` で始まる | コーナー名と直後の空白を除く（`ショート 紫式部` → `紫式部`） |
| それ以外 | シリーズ名のまま |

`title` がコーナー名で始まれば検査が赤になる。

## 3. `id`

`id` は `title` の読みをローマ字にした kebab-case である。
事物の `seriesId`・エピソードの `seriesId`・典拠のファイル名がこの値を指すので、後から変えると参照がすべて変わる。

| `title` の部分 | 規則 | 例 |
|---|---|---|
| 漢字とかな | 日本語の読みをローマ字にする | `yoshida-shoin`・`shokatsu-komei` |
| カタカナの外来固有名 | 元の言語の表記を使う | `sparta`（`suparuta` でない）・`hitler`・`cleopatra` |
| 長音 | 記号でも母音の重ねでも表さない | `shukyo`（`shūkyō`・`shuukyou` でない）・`komei` |
| `・`・`＝`・序数 | `-` と算用数字へ置き換える | `roshi-soshi`・`levi-strauss`・`elizabeth-1` |
| 助詞 | 語として残す | `okane-no-rekishi`・`saicho-to-kukai` |
| コーナー名 | `title` と同じく除く | |

1 つの `title` に漢字とカタカナが混ざるときは、部分ごとに上の規則を当てる（`america-kaitakushi`・`teisei-roma`）。
検査が見るのは重複だけで、読みどおりかは見ない。

## 4. 代表点と `kind`

次の二つを順に問う。

1. 代表点を 1 つ置くと嘘になるか。
   同じ仕組みが各地で独立に立ち上がる主題（お金の歴史・世界三大宗教）は嘘になる
2. 主題そのものが土地に在るか。
   人物を追うシリーズでも、主題が思想なら土地に無い（老子・荘子）

| 1 の答え | 2 の答え | `anchor` | `kind` | 現物の例 |
|---|---|---|---|---|
| 嘘になる | 問わない | `"unlocated"` | `concept` | 世界三大宗教・お金の歴史 |
| 嘘にならない | 在る | 事物の `id` | `place` | スパルタ → `sparta-city`・吉田松陰 → `hagi` |
| 嘘にならない | 無い | 事物の `id` | `concept` | 老子・荘子 → `luyi` |

`kind: place` と `anchor: "unlocated"` の組は検査が赤にする。
位置なしのシリーズは `loci.geojson` に事物を足さない。

代表点を置くときは、活動の中心地か舞台の代表地点を 1 点選ぶ。
正確さは求めない。
`loci.geojson` へ足す Feature の形は、`docs/ARCHITECTURE.md` §3 の例と現物に揃える。
`coordinates` は GeoJSON の順なので、経度が先で緯度が後である。
緯度と経度を入れ違えても検査は赤にならない。

事物の `id` は次の表で決める。

| 状況 | 事物の `id` | 例 |
|---|---|---|
| 代表点の地名を他のシリーズが要求していない | 代表点の地名をローマ字にする | `xianyang`・`carthage` |
| 同じ地名を二つのシリーズが要求する | より具体的な地点名をローマ字にする | `sparta-city`・`forum-romanum` |

人名やシリーズ名を事物の `id` にしない（シリーズ `hannibal` の代表点は `carthage`）。
検査が見るのは重複と `unlocated` の使用だけで、地名かどうかは見ない。

## 5. `region`

`region` はそのシリーズが扱う地理の広がりを表し、代表点の在る区画とは独立に決まる。
位置なしのシリーズも区画を持てる。

値は次の 13 個から 1 つ選ぶ。
一覧の正は `web/src/lib/schema/series.ts` の `SERIES_REGIONS` で、値を足すには新しい ADR が要る。

`日本` / `朝鮮半島` / `中国` / `東南アジア` / `南アジア` / `中央ユーラシア` / `西アジア` / `アフリカ` / `ヨーロッパ` / `北アメリカ` / `南アメリカ` / `オセアニア` / `地域なし`

次の表を上の行から当て、最初に当てはまった行の値を書く。

| 順 | 状況 | 値 | 例 |
|---|---|---|---|
| 1 | 扱う地理が一区画に収まる | その区画 | 秦の始皇帝 → `中国`・ショート 切腹（位置なし） → `日本` |
| 2 | 複数の区画に跨るが、本拠（出自・活動の中心・帰る場所）が一つある | 本拠の区画 | アレクサンドロス → `ヨーロッパ`・ハンニバル（遠征先はヨーロッパ） → `アフリカ` |
| 3 | 跨りが対等で本拠が無い | `地域なし` | 世界三大宗教 |

`地域なし` を選ぶかどうかは `anchor` が `"unlocated"` かどうかと独立で、本拠を一つ言えるシリーズには使わない。

代表点や本拠が二つの区画に読める位置にあるときは、次の表に従う。

| 継ぎ目 | 区画 |
|---|---|
| ロシア | ウラル山脈以西は `ヨーロッパ`、以東は `中央ユーラシア` |
| 北アフリカ（エジプトを含む） | `アフリカ` |
| アナトリア | `西アジア`（イスタンブールの欧州側も含め、トルコを割らない） |
| モンゴル高原・中央アジア | `中央ユーラシア`（チベットと満洲は `中国`） |
| メキシコ・中米・カリブ | `北アメリカ` |

検査が見るのは 13 値のどれかであることだけで、区画の選び方は見ない。

## 6. `tags`

`tags` は種別を最低 1 つと主題を 0 個以上持ち、合わせて 4 個以内である。

### 種別

当てはまる種別をすべて入れる。
一覧の正は `web/src/lib/schema/series.ts` の `SERIES_CATEGORY_TAGS` である。

| 値 | 当てるもの | 現物の例 |
|---|---|---|
| `人物` | 一人か数人の生涯を追う | 吉田松陰・項羽と劉邦 |
| `集団` | 国家・帝国・社会層など、続く人の集まり | スパルタ・帝政ローマ |
| `出来事` | 始まりと終わりのある事の運び | アメリカ開拓史 |
| `概念史` | 主題を時代を跨いで追う | お金の歴史・世界三大宗教 |

人物と出来事の両方であるシリーズ（サラディンと十字軍）は `人物` と `出来事` を両方入れる。
種別は `kind` と別の軸なので、老子・荘子は種別が `人物` で `kind` が `concept` である。

### 主題

1. 手順 1（現物を読む）で数えた既存の語から選ぶ
2. 既存のどの語でも言えないときだけ、新しい語を足す

| 入れない | 例 |
|---|---|
| 地域名 | `日本`・`ギリシア` |
| `catalog/eras.json` と同じ粒度の時代名 | `先史`・`古代`・`中世`・`近世`・`近代`・`19世紀`・`20世紀`・`戦後` |
| コーナー名 | `ショート`・`ジンブンガク` |

era より細かい固有の時代名は入れてよい（`幕末`・`三国志`）。

検査が見るのは種別の有無・個数・era と同じ粒度の時代名で、地域名とコーナー名と、既存の語と同じ意味の新語は見ない。

## 7. 検査と見直し

`web/` で `pnpm check` を回し、緑にする。
緑になった後に、検査で見られない次の判定を見直す。

| 見直すこと | 当て直す手順 |
|---|---|
| `id` が読みどおりか | 手順 3（`id`）の表 |
| 事物の `id` が地名か | 手順 4（代表点と `kind`）の事物の `id` の表 |
| `coordinates` が経度・緯度の順か | 手順 4（代表点と `kind`） |
| `region` を区画にするか `地域なし` にするか | 手順 5（`region`）の表を上の行から当て直す |
| `tags` に地域名とコーナー名が無いか | 手順 6（`tags`）の「入れない」の表 |
| 新しく足した主題が既存の語と同じ意味でないか | main を取り込み、手順 1（現物を読む）の集計を回し直す |

## 8. 典拠を記録する

`@historian`（`.github/workflows/claude-history-review.yml`）の裏どりが返り、人間が値を決めた後に、典拠を `docs/sources/<シリーズ id>.md` へ記録する。
ファイルが在ることがそのシリーズの裏どりが済んだ印になるので、裏どりの前にファイルを作らない。
レコードの書式は [ADR-0037（典拠の層）](../../../docs/adr/0037-sources-layer.md) が持ち、節の並びは `docs/sources/README.md` が持つ。
`pnpm check` はファイルと `catalog/` の値の対応を見ないので、記録した後に `catalog/` の値を動かしたら同じファイルも直す。

## 規則が決めていない表記に当たったとき

元の言語がラテン文字でない名の転写や事物の `id` のローマ字の方式のように、ADR-0034 が決めていない表記に当たったら、既存の現物に揃え、選んだ表記と根拠を PR 本文に書く。
規則を足すには ADR-0034 を supersede する新しい ADR が要るので、このスキルへ規則を書き足さない。
