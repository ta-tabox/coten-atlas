# データの配り方を決める（バンドルか fetch か）

**前提**: #3 ／ **担当**: Claude（決定は人間と合意） ／ **参照**: `docs/plan.md` §1「スタック」、§2、#5

## 目的
static export では実行時にサーバが無いので、`themes.geojson`（最終的に90前後）と `episodes.json`（数百〜千件）をどう届けるかで初期表示のバイト数が決まる。
#5（描画）はどちらかを前提にして読み込み口を書くので、書き始める前に決める必要がある。
zod の検査をビルド時だけで閉じるか実行時の読み込み口でも通すかも、同じ判断の裏表なのでここで一緒に決める。

## 作るもの（決定と文書の改訂）
- **配り方の決定** — `import` してバンドルへ載せるか、`public/` に置いて `fetch` するか。
  テーマは載せてエピソードは fetch、のような分割も候補に入れる
- **検査を走らせる場所の決定** — `scripts/validate-data.ts`（ビルド時）だけで閉じるか、実行時の読み込み口でも `parseThemes` を通すか
- **判断の根拠** — 90テーマ・1000エピソード時点の概算バイト数を出してから決める。数字を plan.md へ残す
- `docs/plan.md` §2 の末尾へ「配り方」の段落を追記
- #5 の「作るもの」へ読み込み口を追記
